# Игровые данные (`data/`)

Содержимое игры — CSV-файлы, а не C++. Движок знает только схему; файлы задают, что именно существует.
`mapcraft_editor` пишет те же файлы, которые читает игра. Геометрия карты живёт отдельно, в `build/map/world.mcmap`.
«Истории» как в EU4 нет: одна дата старта (зашита в `game/calendar.h`, не в `data/`).

Сейчас в `data/` только заголовки: содержимое мира Майнкрафта задаёт пользователь. Схема ниже унаследована от
Tamriel Universalis и будет меняться вместе со спецификациями (POPs, товары, RGO, заводы).

## Файлы
- Формат: CSV UTF-8, первая строка — заголовок.
- Ссылки между файлами — только по строковым ключам: латиница, `snake_case`; у стран — тег из трёх заглавных букв.
- Номера существуют только в памяти: их раздаёт загрузчик по порядку строк.
- Цвет записывается как `#RRGGBB`, пустая ячейка значит «не задано».

| Файл | Колонки | Что |
|---|---|---|
| `common/terrain.csv` | key, name, color | логический terrain провинций (не вид карты) |
| `common/biomes.csv` | key, name, color | биомы вида карты: `color` — цвет в `biome.png`. Пока его читают только инструменты карты (`tools/mapgen/biomes.py`); блоки поверхности и оттенки добавятся с рендером блоков |
| `common/countries.csv` | tag, name, adjective, color | определения стран; `adjective` — для частей, отрезанных от столицы, по умолчанию = name |
| `common/culture_groups.csv` | key, name | группы культур |
| `common/cultures.csv` | key, name, color, group | культуры |
| `common/religion_groups.csv` | key, name | группы религий |
| `common/religions.csv` | key, name, color, group | религии |
| `common/trade_goods.csv`, `trade_nodes.csv` | key, name, color | необязательны, пока нет торговли |
| `setup/provinces.csv` | id, name, owner, controller, cores, terrain, tax, production, manpower, culture, religion, trade_good, trade_node, center_of_trade | провинции суши на старте |
| `setup/countries.csv` | tag, capital, primary_culture, religion | страны на старте: столица (id провинции), основная культура, государственная религия |

Подробности `setup/provinces.csv`:
- `id` — номер провинции карты;
- `name` нужен только человеку и для diff, загрузчик его не читает;
- `cores` — теги через пробел;
- development — числа ≥ 0;
- `center_of_trade` — 0 или 1.

Провинция без владельца допустима. Морских строк пока нет.

Номера провинций в `setup/provinces.csv` — это id карты. **Перенумерация карты (`edit_provinces.py sync-lakes`) этот
файл сейчас не переписывает.** Его нужно переписать вместе с картой, иначе данные съедут на чужие провинции.

**Проверка при загрузке.** Неизвестный ключ или тег, повтор, id не суши или плохое число — это ошибка с файлом и
строкой, а не тихий ноль. Столица вне владений своей страны — только предупреждение: через такое состояние проходит
правка в редакторе, и редактор показывает его в панели «Countries». Проверить данные без окна:
`mapcraft_editor --check`.

## В памяти (`code/src/game/game_data.h`)
- **Содержимое и состояние — разные типы.**
  - `Content` — справочники и `CountryDefinitions` (тег упакован в `u32`, имя, прилагательное, цвет). Все строки
    живут только здесь; после загрузки не меняется.
  - `WorldState` — только столбцы: `Provinces` и `CountryStates` (столица, основная культура, религия) с тем же
    индексом, что у стран. Симуляция меняет только его.
- **Индексы.** Провинция и страна — `u16`, 0 = нет; провинции 1..N, как в карте. Terrain, культура, религия, группы,
  товар и узел — `u8`, 0 = нет, поэтому в каждом списке не больше 255 записей (проверяется).
- **Раскладка.** Каждое поле — свой столбец длиной N+1, дополненной до кратной 16, с выравниванием 64 байта
  (`Column<T>`, `AlignedAllocator`). Цикл по провинциям идёт по столбцу подряд.
- **Числа — `float`.** Мультиплеера и реплеев не будет, детерминизм между машинами не нужен.
- **Коры** — битовая матрица провинция × страна (по `u64`-слову на 64 страны).
- **Владение:**
  - в игре `GameData` принадлежит `game/World`, наружу он отдаёт только `const`;
  - карта (`App::set_game`) и UI только читают;
  - редактор держит свой `GameData` и правит только `state`; undo хранит снимки `WorldState`.

## Время
Единица времени — день. Всё это код, не данные: календарь и старт в `data/` не лежат.
- **Календарь** (`game/calendar.h`) — заглушка до спецификации сеттинга: 12 месяцев (January … December) по 30 дней,
  год — 360. Дата — число дней от 1 January, year 1; `Date` {год, месяц, день} получается из него без хранения. Старт
  — 1 January 1; формат `17 August 201`. Дней недели нет.
- **Дата** — одно число, поэтому лежит в `World` (`day()`, `date()`), а не среди столбцов `WorldState`. Меняет её только
  `World::tick_day()`; `World::restart()` возвращает старт.
- **Темп** (`game/pace.h`) — чистый тайминг, мира не знает: скорость 1–5 и пауза. Скорости 1–4 — месяц за 60, 30, 15 и
  7 секунд; скорость 5 — как позволяет CPU: тики подряд, пока не истёк бюджет кадра (`Pace::kFrameBudget`, 8 мс), но
  минимум один. Кадр длиннее `Pace::kMaxFrame` (0.25 с) на скоростях 1–4 считается таким, чтобы не сыпать днями после
  затыка. Новая партия начинается на паузе, скорость 3.
- **Кто кого зовёт.** `Shell::frame` → `Session::advance(World&, dt)` → `Pace::advance` → `World::tick_day()` на каждый
  набежавший день. Вне фазы `playing` время стоит. `World` передаётся в `advance` на время вызова, `Session` его не
  хранит. Тик идёт до отрисовки карты и UI в том же кадре.
- **Ограничение.** Пока тик — это `++day_`, скорость 5 за кадр делает сотни тысяч дней: бюджет уходит на пустой цикл.
  Настоящая цена дня появится вместе с симуляцией. Счётчик дней — `u32` (около 11 млн лет).
