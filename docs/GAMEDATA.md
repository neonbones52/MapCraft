# Игровые данные (`data/`)

Содержимое игры — CSV-файлы, а не C++. Движок знает только схему; файлы задают, что именно существует.
`mapcraft_editor` пишет те же файлы, которые читает игра. Геометрия карты живёт отдельно, в `build/map/world.mcmap`.
«Истории» как в EU4 нет: одна дата старта (зашита в `game/calendar.h`, не в `data/`).

Данные в `data/` черновые, заполняет их пользователь в `mapcraft_editor`.

Экономика будет EU3-lite (docs/ECONOMY.md); правил экономики в коде пока нет. У провинции — товар (trade good),
`base_tax` и население; рынки регионов стали торговыми узлами (trade nodes в
смысле центров торговли EU3, без графа между узлами; правила — срез M14, docs/ECONOMY.md, «Торговые узлы»).

## Файлы
- Формат: CSV UTF-8, первая строка — заголовок.
- Ссылки между файлами — только по строковым ключам: латиница, `snake_case`; у стран — тег из трёх символов
  (заглавные латинские буквы или цифры).
- Номера стран и записей списков существуют только в памяти: их раздаёт загрузчик по порядку строк. Провинции —
  исключение: их номер — `id` карты.
- Цвет записывается как `#RRGGBB` и обязателен; в остальных колонках пустая ячейка значит «не задано».

| Файл | Колонки | Что |
|---|---|---|
| `common/terrain.csv` | key, name, color, movement_cost | логический terrain провинций (не вид карты); ставится руками в редакторе; `movement_cost` — во сколько раз дольше шаг в провинцию с ним, чем на равнину (1), > 0 («Движение армий») |
| `common/biomes.csv` | key, name, color, density, minecraft_biome, top, side, under, deep, shore, snow_top, snow_side, snow_line, trees, tree_density, tree_line, village | биомы вида карты (см. ниже); не игровые данные, редактор его не правит |
| `common/countries.csv` | tag, name, adjective, color | определения стран; `adjective` — для частей, отрезанных от столицы, по умолчанию = name |
| `common/goods.csv` | key, name, color, price, icon | товары (набор — пользователя, растёт строками: без фабрик и рецептов, cattle — и мясо, и кожа); `price` — базовая цена товара (base price EU3/EU4) в изумрудах за единицу производства, > 0 (у изумруда всегда 1); от неё мировая цена, которую будут менять модификаторы и события; правила её пока не читают; `icon` — предмет Майнкрафта для UI (M13), пока не читается |
| `common/trade_nodes.csv` | key, name, color | торговые узлы; узел — из целых регионов (`setup/regions.csv`); необязателен; правил узлов пока нет (M14) |
| `common/regiment_types.csv` | key, name, category, maneuver, off_fire, def_fire, off_shock, def_shock, off_morale, def_morale | типы полков — юниты (как Latin Knights в EU4); `category` — infantry, cavalry или artillery; `maneuver` — манёвр юнита EU4, дальность удара вбок (фланг; пехота 1, конница 2); пипсы атаки и защиты огня, натиска и морали — целые 0–255 («Бой»); необязателен (без него — без полков) |
| `common/defines.csv` | key, value | константы боя (`NDefines::NMilitary` EU4), каждая обязательна, по строке: `days_per_phase`, `dice_sides`, `cannot_retreat_days`, `overrun_factor`, `overrun_factor_cannot_leave`, `max_combat_width` (≤ 40) — целые ≥ 1; `war_length_damage`, `daily_morale_damage`, `reserve_daily_morale_damage`, `front_line_modifier` — десятичные («Бой») |
| `common/modifiers.csv` | key, name, modifier, value | наборы модификаторов — источники («Модификаторы» ниже): строка на пару «набор — модификатор»; `key` — набор, `name` — имя для людей (на любой строке набора, где есть — одинаковое; по умолчанию key), `modifier` — модификатор из списка кода, в наборе один раз, `value` — число (может быть отрицательным); набор `base` есть у каждой страны (base_values EU4); необязателен |
| `setup/provinces.csv` | id, name, owner, controller, cores, terrain, good, base_tax, population | провинции суши на старте (docs/ECONOMY.md, «Провинция») |
| `setup/regions.csv` | region, name, trade_node | регион карты (номер из `regions.csv` карты) → торговый узел; пусто — без узла |
| `setup/countries.csv` | tag, capital, modifiers | страны на старте: столица (id провинции); `modifiers` — ключи наборов `common/modifiers.csv` через пробел (`base` — нельзя, он у всех) |
| `setup/armies.csv` | army, province, owner | армии на старте (только сухопутные): `army` — номер в файле, для `regiments.csv`; `province` — провинция суши; имени нет (имя по слоту, «1st Army»); необязателен |
| `setup/regiments.csv` | army, type, strength | полки армий: `army` — номер из `armies.csv`, `type` — ключ `regiment_types.csv`, `strength` — люди, целое (полный полк 1000); мораль на старте полная — макс. мораль страны-владельца армии («Модификаторы»); необязателен |

Подробности `common/biomes.csv` (читают инструменты карты и игра при запуске, docs/RENDER.md «Облик блоков»):
- `color` — цвет биома в `biome.png`; `density` — плотность провинций при генерации карты (1 — обычная, меньше —
  провинции крупнее);
- `minecraft_biome` — ванильный биом (`data/minecraft/worldgen/biome/<имя>.json` в jar), чьи температура, осадки и
  цвета дают оттенок травы и воды;
- блоки — имена текстур `assets/minecraft/textures/block/<имя>.png` из jar: `top` — верх, `side` — бок верхнего блока,
  `under` — бок следующих трёх, `deep` — глубже, `shore` — верх и бок берега (суша на блок выше моря или озера);
- `snow_line` — высота ступени (0–16, как `height` в корневом `provinces.csv` карты), с которой верх — `snow_top`, бок верхнего блока —
  `snow_side`; пусто — снега нет, тогда `snow_top` и `snow_side` можно не заполнять;
- `trees` — деревья: имена configured feature из jar (`data/minecraft/worldgen/configured_feature/<имя>.json`)
  через пробел, повтор — больший вес; поддержаны деревья с прямым и раздвоенным стволом (листва blob, spruce,
  acacia), столбики блоков (кактус) и одиночные блоки (сухой куст); `tree_density` — доля блоков карты с деревом (0–1, не
  больше дерева на блок); `tree_line` — ступень, с которой деревья не растут (пусто — растут везде);
- `village` — стиль домиков-городов (деревни Майнкрафта): `plains`, `desert`, `savanna`, `taiga`, `snowy`; выше
  `snow_line` биома — всегда `snowy`;
- биом, который есть в `world.mcmap`, обязан быть в таблице (ключ — `key`); правка блоков и оттенков видна после
  перезапуска, без пересборки карты; новый биом или новый `color` — правка `biome.png` и `bake.py`.

Флаги стран — `<TAG>.png` в папке `assets/flags` (путь задаётся при сборке, `MC_DEFAULT_FLAGS`; в репозитории папки
нет, картинки в git не идут). Файл необязателен: без него флаг — квадрат цвета страны. Решение пользователя на будущее —
флаги-баннеры с узорами (данные, не арт; docs/UI.md).

Подробности `setup/provinces.csv`:
- `id` — номер провинции карты;
- `name` нужен только человеку и для diff, загрузчик его не читает. Имя провинции живёт в двух местах: корневой
  `provinces.csv` карты (из него запекаются надписи) и эта колонка — переименовывать по id в обоих;
- `cores` — теги через пробел;
- `good` — товар провинции, ключ из `common/goods.csv`. Обязателен каждой провинции суши: без него — предупреждение
  загрузки и `--check` (не ошибка: у провинции суши без строки, новой на карте, товара нет, пока его не поставит
  редактор). Товар и terrain ставит пользователь руками: код не ограничивает и не подсказывает, что где может быть;
- `base_tax` и `population` — числа ≥ 0, пусто — 0 (смысл — docs/ECONOMY.md, «Провинция»).

`trade_nodes.csv` и `modifiers.csv` необязательны; обязательны `terrain.csv`, `goods.csv` (товар у провинции обязателен) и
`countries.csv`, `defines.csv` (константы боя).

Столица страны — `capital` в `setup/countries.csv`; без неё (или если провинция не своя) столицей считается первая
провинция страны, наименьший id (`seat`, `game/countries.h`).

Провинция без владельца допустима. Морских строк пока нет.

Номера провинций в `data/setup` — это id карты. **Ссылка на провинцию** в `data/setup` — колонка `id` в
`provinces.csv`, `capital` в `countries.csv`, а в любом другом файле — колонка `province` (так и называть её в новых
файлах). Ссылка на регион — колонка `region`, номер региона карты (1-based, `PREG`): номера регионов при правке
провинций не меняются. Перенумерация карты (`edit_provinces.py sync-lakes`, когда удаляется озеро) переписывает именно эти колонки
на новые id (`SETUP_COLUMNS` в скрипте), строки `provinces.csv` — в новом порядке. Строка удалённой провинции в
`provinces.csv` выбрасывается; любая другая ссылка на неё останавливает правку до записи файлов.

**Проверка при загрузке.** Неизвестный ключ или тег, повтор, id не суши или плохое число — это ошибка с файлом и
строкой, а не тихий ноль. Предупреждения (лог, `mapcraft_editor --check` и панель «Countries» редактора) — то, через что
проходит правка:
- столица вне владений своей страны;
- дисциплина, макс. мораль, тактика или ширина фронта страны не больше 0;
- когда торговые узлы есть: регион без узла и узел без регионов.

Проверить данные без окна: `mapcraft_editor --check`.

## В памяти (`code/src/game/game_data.h`)
- **Содержимое и состояние — разные типы.**
  - `Content` — справочники и `CountryDefinitions` (тег упакован в `u32`, имя, прилагательное, цвет). Все строки
    живут только здесь; после загрузки не меняется.
  - `WorldState` — только столбцы: `Provinces`, `Regions` (торговый узел региона), `Balances` (деньги),
    `CountryStates` (столица, наборы модификаторов) с тем же индексом, что у стран, и таблицы сущностей `Armies`,
    `Regiments` и `Battles` (ниже). Симуляция меняет только его. Столбцы заданы списками (ниже).
- **Метки** (`game/game_data.h`, у каждой структуры): **сохраняется** — `WorldState` и его части, то, что меняют дни
  и что попадёт в сейв; **контент** — `Content` и его части, неизменны после загрузки `data/common` и карты; **кэш** —
  рабочие данные правил, после загрузки и `restart` строится из двух первых, не сохраняется: `Cache` в `GameData`
  (суммы модификаторов стран, перестраивает `GameData::rebuild_cache`) и кэши самих правил (граф марша — `Movement`,
  бой — `Combat` в `World`). Размеры (`count`, `core_words`) — ни то, ни другое: следуют из контента и карты. Дата (`World::day`) и
  `seed` мира тоже сохраняются, но лежат в `World`.
- **Списки столбцов (X-macro).** У каждой таблицы `WorldState` рядом со структурой — свой список
  (`MC_PROVINCE_COLUMNS`, `MC_REGION_COLUMNS`, `MC_BALANCE_COLUMNS`, `MC_COUNTRY_COLUMNS`): строка
  `X(таблица, тип, имя, старт)` на столбец, в порядке сохранения. Из списка раскрываются поля, `resize`,
  `for_each_saved` и чтение-запись `data/setup`; новый столбец — одна строка. Старт столбца:
  - `runtime` — 0 на старте, дальше меняет только игра (`money.cash`);
  - `setup("колонка", разбор)` — из `data/setup`, редактор пишет обратно; разбор: `country` (тег, пусто — нет; `u16`),
    `key(&Content::список)` (ключ справочника, пусто — нет; `u8`), `number` (число ≥ 0, пусто — 0; `float`), `whole` (целое ≥ 0, пусто — 0; `i32`). Тип
    столбца, который не подходит разбору, не компилируется. Колонки нет в файле — ошибка загрузки;
  - `by_hand` — из `data/setup`, но читает и пишет свой код `GameData` (столица и провинция армии — провинция суши,
    армия полка — номер из `armies.csv`);
  - `derived` — не в `data/setup`: `GameData` ставит при загрузке из других столбцов (мораль полка — полная).
  Вне списков, явно: размеры (`count`, `core_words`, `modifier_words`), битовые матрицы коров и наборов
  модификаторов стран, маски живых слотов и маска отступающих армий (`armies.retreating`). Ключ строки (`id`, `region`, `tag`) и
  `name` для людей — тоже свой код каждого файла. Метки «сохраняется / контент / кэш» — у типа, не у столбца; у кэша
  свои структуры со своими списками, без `for_each_saved` (обход — `for_each_cached`, `game/modifiers.h`).
- **Порядок колонок `data/setup`** — какой был в файле при загрузке (`GameData::setup_layout`), `save_setup` его
  сохраняет; колонки, которых в файле не было (файла не было), идут в конец: сначала свои, потом из списка.
  Колонки, которых игра не знает, при сохранении пропадают.
- **Список сохраняемого** — `game/saved_state.h`, `for_each_saved`: каждый столбец и число `WorldState` под
  стабильным именем (`provinces.owner`, `regions.trade_node`…), в одном порядке, столбцы целиком с дополнением:
  столбцы списков, коры — после столбцов провинций, наборы модификаторов (`countries.modifiers`) — после
  столбцов стран; у таблиц слотов — только занятая часть (слоты до конца слова маски
  с последним живым, `used_slots`; остальное нулевое), иначе дамп и сумма каждый день шли бы по 65 тысячам пустых слотов. По нему идут дамп и контрольная сумма `mapcraft_sim`, позже —
  сейв. `static_assert` на `sizeof(WorldState)` считает столбцы списков сам и ловит новое поле вне списков, которое
  забыли разметить и внести в `for_each_saved`.
- **Правки сценария.** `GameData::load` принимает `csv::Patch` (`mapcraft_sim`, docs/SIMULATION.md): поле файла
  `data/` меняется в тексте до разбора, поэтому проверки те же; правка мимо файла, строки или колонки — ошибка. Игра и
  редактор правок не передают.
- **Сущности — слоты** (`Armies`, `Regiments`, `Battles`; `game/armies.h`). Армии, полки и бои рождаются и гибнут,
  поэтому у таблицы постоянное число слотов (`kArmySlots` = 4096, `kRegimentSlots` = 65536 — потолок слота `u16`;
  больше — слоты `u32`; `kBattleSlots` = 1024, бой — один на провинцию), маска живых
  слотов `alive` (`u64`) и выдача наименьшего свободного слота — в тике нет выделений, порядок детерминирован.
  Освобождённый слот обнуляется по списку столбцов. Слоты берут и освобождают только функции `game/armies.h`
  (`create_army`, `destroy_army` — вместе с полками, `add_regiment`, `remove_regiment`); обход — `for_each_alive`
  по порядку слотов. Ссылка на армию извне (команда, бот, UI) — `ArmyRef` (слот + поколение): `generation` растёт
  при каждом освобождении слота, и старая ссылка больше не разрешается (`resolve`). Полк ссылается на армию просто
  слотом. Имя армии — не данные: порядковый номер слота («1st Army», `ui/army_name.h`). При загрузке армии
  занимают слоты по порядку файла; `save_setup` пишет живые армии в порядке слотов с номерами 1, 2, …
  Марш армии — столбцы `next`, `destination`, `progress` (`runtime`, «Движение армий»).
- **Индексы.** Провинция и страна — `u16`, 0 = нет; провинции 1..N, как в карте. Terrain, товар, торговый
  узел и тип полка — `u8`, 0 = нет, поэтому в каждом списке не больше 255 записей (проверяется).
- **Раскладка.** Каждое поле — свой столбец длиной N+1, дополненной до кратной 16, с выравниванием 64 байта
  (`Column<T>`, `AlignedAllocator`). Цикл по провинциям идёт по столбцу подряд.
- **Числа — `float`**; балансы и требования — `i64` (docs/ECONOMY.md, «Деньги в i64»); модификаторы и бой — `Fixed`
  (`core/fixed.h`: `i32`, 1000 = 1.0, усечение после каждой операции, как `CFixedPoint` EU4): мораль полка, его сила
  в людях (`i32`), значения и суммы модификаторов. Симуляция
  строго детерминирована (мультиплеер будет): правила — docs/SIMULATION.md, «Детерминизм».
- **Коры** — битовая матрица провинция × страна (по `u64`-слову на 64 страны); наборы модификаторов стран — так же,
  страна × набор.
- **Владение:**
  - в игре `GameData` принадлежит `game/World`, наружу он отдаёт только `const`;
  - карта (`App::set_game`) и UI только читают;
  - редактор держит свой `GameData` и правит только `state`; undo хранит снимки `WorldState` (64 шага); после
    каждой правки, undo и redo — `rebuild_cache`.

## Модификаторы (`game/modifiers.h`)
Общий механизм правил EU3 (docs/SIMULATION.md, «Модификаторы»): источник → модификатор → значение.
- **Модификаторы** — список кода `MC_COUNTRY_MODIFIERS` (`game/game_data.h`), строка `X(имя)` на модификатор; имя —
  его ключ в данных. Сейчас: `discipline` (дисциплина, 1 = 100%), `base_morale` (база макс. морали полков, число;
  в EU4 её даёт технология), `land_morale` (доля к базе, «мораль армий» EU4: +0.1 — +10%), `military_tactics`
  (тактика EU4), `combat_width` (ширина фронта, целая), `infantry_fire`, `infantry_shock`, `cavalry_fire`,
  `cavalry_shock` (урон оружия категории в фазе — числа техов EU4). Новый модификатор — строка списка и формула,
  которая его читает.
- **Числа — `Fixed`** (`core/fixed.h`): значение из файла разбирается точно (до трёх знаков после точки), суммы —
  целые сложения, как `CFixedPoint` EU4.
- **Источник — набор** (`common/modifiers.csv`, контент `ModifierBundles`): у набора значения по модификаторам,
  столбец на модификатор по наборам. Набор `base` есть у каждой страны и задаёт базу — числа военной техи 3 EU4 (решение пользователя
  26.11.2026), кроме ширины: дисциплина 1, `base_morale` 2.5, `military_tactics` 0.5, `combat_width` 15 (в EU4 на
  техе 3 — 20), `infantry_fire` 0.35, `infantry_shock` 0.5, `cavalry_shock` 1; технологии потом прибавят к суммам;
  остальные — у страны в наборе `countries.modifiers` (сохраняется: потом его будут менять форма правления, идеи,
  события). Модификаторов провинций пока нет: их список и суммы придут с первым правилом, которое их читает.
- **Значения складываются** (решение пользователя 26.11.2026, как EU4 и Divine Wind): сумма страны по модификатору —
  значение `base` плюс значения её наборов, по порядку наборов в файле; что значит сумма (число или доля, где 0.1 —
  +10%), решает формула, которая её читает.
- **Суммы — кэш** `CountryModifiers` (`Cache` в `GameData`): столбец на модификатор по странам; строит
  `sum_country_modifiers` проходом по странам на каждый набор, без ветвлений внутри (маска, не `if`); перестраивается после загрузки,
  `restart` и правки в редакторе (`rebuild_cache`). В тике сумм пока не меняет ничего.
- **Правила читают только формулы** `game/modifiers.h`: `discipline`; `max_morale` = `base_morale` × (1 +
  `land_morale`) (у модификатора и формулы разные имена, чтобы база не путалась с итогом); `tactics` =
  `military_tactics` × `discipline` (`GetMilitaryTactics` EU4: на неё делится урон по полкам страны — так дисциплина
  цели снижает получаемый урон); `combat_width`; `weapon` (категория, фаза). Их читают бой, полная мораль полка
  (загрузка и новый полк в редакторе), плашка и подсказка армии.
- Предупреждение загрузки: дисциплина, макс. мораль, тактика или ширина страны не больше 0 (нет набора `base`).
- `mapcraft_sim` пишет суммы в `cache.csv` папки прогона и сверяет кэши двух прогонов в конце (docs/SIMULATION.md).
- Правка сценария (`csv::Patch`) находит строку по первой колонке, а у набора их несколько: значения
  `modifiers.csv` сценарием пока не поправить.

## Бой (`game/combat.h`)
Сухопутный бой EU4 1.37.5 день за днём в порядке операций eu4.exe, как его воспроизводит BattleSim
(`CCombat::DailyUpdate`, `FireAt`, `ArrangeBattleField`, `ReorganizeTroops`, `CheckOverrun`, `WillLose`), в `Fixed`.
Сейчас — база (решение пользователя 26.11.2026): фазы, кубики, пипсы, мораль, дисциплина, тактика, расстановка, цели
по манёвру, стеквайп, отступление. Ещё нет: генералы, местность и переправы (глобальный модификатор кубика — 0),
вторая линия артиллерии (артиллерия стоит в резерве: резерв EU4 не выводит её в линию; теряет мораль резерва и
считается в людях), нехватка поддержки конницы, combat ability и модификаторы урона (все 0), восстановление морали
вне боя.
- **Враги до дипломатии** — все чужие армии (решение пользователя). У боя две стороны, по стране: защитник — страна
  первой (по слоту) армии, стоявшей в провинции до сегодня, иначе первой; атакующий — первая другая страна, пришедшая
  сегодня, иначе первая другая. Третья страна ждёт конца боя. Армии двух стран боя, входящие в провинцию, вступают в
  него (`TryToJoin`): полки — в конец резерва своей стороны (`AddUnit`), с той моралью, что есть. Вступившая армия
  останавливает марш; приказ армии в бою и отступающей отклоняется.
- **День** (`World::tick_day`: команды → марш → бой): конец отступлений, которые пришли; новые бои и вступления; у
  каждого боя по порядку слотов — до выстрелов: длительность +1; в первый день кубики, расстановка
  (`ArrangeBattleField`), заполнение линии и стеквайп ×10 до первого выстрела; раз в `days_per_phase` дней — новые
  кубики и смена фазы огонь ↔ натиск; перестроение обеих сторон (`ReorganizeTroops`); выстрелы атакующего, потом
  защитника, урон копится. Потом урон дня ложится на все полки разом плотным проходом без ветвлений (`ApplyDamage`),
  полки без людей освобождают слот (`DeleteEmptySubUnits`), армии без полков гибнут; потом у каждого боя — исход
  (`WillLose` атакующего первым, `CombatEnds`) или стеквайп ×2 до `cannot_retreat_days`.
- **Выстрел** (`FireAt`): `x = clamp(пипсы фазы + кубик + 2, 0, 21)`, база `25 + 25x`; люди: × сила × дисциплина ×
  `front_line_modifier` / тактика цели × оружие × 0.2 × (ранги/4 при ударе во фланг) × (1 + `war_length_damage` ×
  день); мораль: макс. мораль стрелка / 2.7 × база по пипсам морали и фазы, те же множители без 0.2 и рангов.
  Множители, которые сейчас 1 (combat ability, урон нанесённый и полученный, урон морали), опущены: умножение на 1.000
  ничего не меняет. Пример вики (кубик 5, теха 3) — 28 человек за выстрел.
- **Цель и манёвр**: полк напротив, иначе первый годный слева направо в пределах манёвра, иначе (если напротив пусто)
  любой в пределах; манёвр = `maneuver` типа × 100/50/25/0% по рангам (сила > 750, 500, 250 людей), не меньше 1.
- **Ширина** — наибольший `combat_width` двух стран, не больше `max_combat_width`; линия — 41 позиция (0..40), обход —
  от центра (21) наружу.
- **Конец**: проигравший отступает, если победитель не в `overrun_factor` раз сильнее (а пока бой нельзя покинуть —
  не вдвое): тогда стёрт, армии гибнут. Победитель получает мораль не ниже макс. × min(0.75, 1.25 × вошедшие люди
  проигравшего / победителя) (`GiveEndOfCombatMoraleBoost`).
- **Отступление** (решение пользователя): в свою провинцию, самую дальнюю от провинции боя по пути марша; своих нет —
  в ближайшую без чужих армий; равенство — меньший id. Пока идёт — бит `armies.retreating`: марш не перехватить,
  боёв армия не начинает и в них не вступает; бит снимается, когда марш окончен. Запрет отступать в оккупированную и
  вражескую — с оккупацией (M7) и дипломатией (M11).
- **Кубики** — `random(seed, день, бой (слот | поколение << 16), назначение) % dice_sides` (`core/random.h`).
- **Состояние** (сохраняется): `Battles` — слоты (`MC_BATTLE_COLUMNS`: провинция, атакующий и защитник, длительность,
  день фазы, фаза, кубики, счётчик очереди резерва, люди, вошедшие на каждую сторону, поколение); `armies.battle`
  (слот боя + 1) и маска `armies.retreating`; `regiments.place` (не в бою, позиция линии + 1, резерв, «ушёл из
  линий» — сломан, но в армии) и `regiments.queue` (порядок резерва EU4 — порядок номеров).
- **Кэш** `Combat` (в `World`, вместимость — при загрузке, в тике без выделений; строится из состояния в начале
  боевой фазы каждого дня, поэтому загрузка и рестарт ничего не меняют): армии по провинциям и полки по армиям (CSR,
  сортировка подсчётом), линии [бой × сторона × 41], очередь резерва (CSR с запасом и ленивым удалением: запись жива,
  пока у полка место «резерв» и тот же номер), урон дня по слотам полков, числа сторон на день (дисциплина, тактика,
  макс. мораль, оружие), итоги сторон (люди, мораль всех и годных).
- В игре: плашки чужих армий красные, когда игрок играет; подсказка провинции показывает бой (стороны, день, фаза,
  кубики). В `mapcraft_sim` — сценарий `battle` (docs/SIMULATION.md).

## Деньги (`core/money.h`, `game/economy/`)
- **Тип.** `Money` — `i64`, целые крупинки, 10⁶ на изумруд. Сумма считается во `float`/`double`, округляется до
  крупинок один раз (`to_grains`), и ровно это целое переходит со счёта на счёт. `to_emeralds` — только для показа.
- **Счета** — `Balances` в `WorldState`: один столбец `cash`. Счетов пока нет: казна стран получит их со срезом казны
  (M8, docs/ECONOMY.md, «Деньги в i64»), а с ней — счётчики потоков по видам.
- **Пишет только `ledger`:** `mint` (доход из ничего), `transfer` (точная сумма между счетами; не уходит в минус),
  `settle` — пакетный расчёт: каждый плательщик платит ровно своё, сумма делится между получателями по весу (каждому —
  целая часть доли), остаток деления — получателю с наибольшим весом (первому из равных), ни одна крупинка не
  теряется. Правила его пока не зовут. Деньги не замкнуты: проверки «сумма балансов = старт + добыто» нет.

## Команды (`game/commands.h`)
- **Команда** — обычные данные без указателей: вид (пока один — `move_army`, идти в провинцию), страна, которая её
  отдаёт, армия — `ArmyRef` (слот + поколение) и провинция.
- **Одна очередь** для игры и `mapcraft_sim` (потом и сети): `World::post` ставит команду на сегодня, место на шкале
  времени — (день, номер), номер считает посты по порядку (в сети его будет выдавать хост). Очередь — столбцы по
  полям команды.
- **Исполняются между днями**, по (день, номер): `World::run_commands` — в начале каждого дня `advance_days` и сразу
  после поста в игре (`Shell`), поэтому приказ в паузе действует мгновенно. Это второй, кроме дня, путь, которым
  меняется `WorldState`, — тоже правила самого `World`. Очередь — не состояние: в игре команды исполняются, как только
  поставлены, `mapcraft_sim` ставит команды дня в его начале, так что между днями очередь пуста.
- **Проверка при исполнении**: армия разрешается по ссылке (погибшей армии или старому поколению приказ не доходит),
  она должна быть страны, отдавшей приказ, а до цели должен быть путь по суше. Иначе ничего не меняется, в лог —
  предупреждение с причиной.

## Движение армий (`game/movement.h`)
Как в EU4 (реверс `CalculateNeighborPaths`, `ProgressMovementOneDay`, `RecalcIsMovementLocked`; EU4
`archeologyEU4/UtilityAI/research/MOVE.md`):
- **Граф переходов** — кэш `Movement`, строится после загрузки из карты и `provinces.terrain`: только суша (пустошь,
  моря и озёра не проходятся; декоративные озёра — суша). Стоимость шага к соседу — длина пути марша в пикселях карты
  (`MapData::march_length`: кривая от точки армии до точки армии только по земле двух провинций, docs/MAPFORMAT.md,
  «Пути марша»; через узкую общую границу она длиннее прямой, и путь через третью провинцию может выйти дешевле —
  Golemtor → Frostheath идёт через Dripstoneshire) × `movement_cost` провинции, **в которую** идёт шаг
  (`terrain.csv`: равнина 1, лес и тайга 1.2, холмы 1.2, пустыня 1.1, болото и горы 1.35, джунгли 1.5 — решение
  пользователя). Туда и обратно поэтому по-разному: в горы дольше, чем с гор. Провинция без terrain — множитель 1.
- **Скорость** — `kMarchPerDay` = 6.3 единицы стоимости в день, у всех родов войск одна. В EU4 — 2.1 (шаг стоит
  пиксели / 3, армия проходит 0.7 в день), но наши провинции в пикселях крупнее: решение пользователя — втрое быстрее.
  Шаг к соседу — медиана 70 px пути марша (прямая — 67 px), около 11 дней по равнине.
- **Путь** — самый дешёвый по стоимостям шагов, при равенстве — к меньшему id; ищется Дейкстрой от цели назад (по
  стоимостям шагов в обратную сторону), поэтому шаг из любой провинции пути не зависит от того, откуда марш начался
  (армия хранит только цель, не путь).
- **Марш по дням**: армия в своей провинции (`province`), пока прогресс шага (`progress`) не дойдёт до его стоимости;
  каждый день к нему прибавляется скорость. Дошёл — армия в следующей провинции (`next`), остаток прогресса
  переходит на следующий шаг; в цели (`destination`) марш кончается, прогресс — 0.
- **Новый приказ и блокировка** (`kMoveLock` = 0.5, EU4 `MOVE_LOCK_PERCENTAGE`): пока прогресс не больше половины
  стоимости шага, приказ действует из провинции, где армия стоит: тот же первый шаг — прогресс сохраняется, другой —
  шаг начинается с 0; приказ в её же провинцию — **отмена**, армия стоит там. Больше половины — шаг заблокирован:
  приказ (и в её же провинцию) действует с провинции, куда шаг ведёт; армия сначала дойдёт туда.
- **Кэш**: граф и рабочие столбцы поиска (`build`, после загрузки), стоимость текущего шага каждой армии и шаг
  после него (`army_after`: куда марш пойдёт из следующей провинции, 0 — там конец; `rebuild_steps`, после загрузки и
  `restart`). Шаг после ищется на шаг вперёд — когда шаг начинается или меняется цель — и при приходе берётся
  следующим шагом: граф не меняется, поэтому это ровно тот шаг, который нашёл бы поиск в этот день; по нему же
  фигурка идёт сквозь провинцию без остановки. Раскладка (CLAUDE.md, «Раскладка данных»): всё — столбцы `Column` (64 байта,
  длина кратна 16), граф — CSR (`offsets_`, `to_`, `cost_`, `back_`), куча поиска — два столбца (стоимость,
  провинция), прибывшие за день — битовая маска `u64`. День марша — явный SSE2 по 8 слотов (`next` → маска, `progress`
  += скорость, сравнение со стоимостью шага, `movemask` в слово маски), без ветвлений; ветвится только разбор
  прибывших по маске, в порядке слотов. Поиск пути — по графу, разрозненный по природе; зовётся только при приказе и
  приходе. В дне нет выделений памяти.

## Время
Единица времени — день. Всё это код, не данные: календарь и старт в `data/` не лежат.
- **Календарь** (`game/calendar.h`) — заглушка до спецификации сеттинга: 12 месяцев (January … December) по 30 дней,
  год — 360. Дата — число дней от 1 January, year 1; `Date` {год, месяц, день} получается из него без хранения. Старт
  — 1 January 1; формат `17 August 201`. Дней недели нет.
- **Дата** — одно число, поэтому лежит в `World` (`day()`, `date()`), а не среди столбцов `WorldState`. Меняет её только
  `World::advance_days(n)` — единственный путь продвижения мира (`n` дней подряд, внутри — закрытый `tick_day`, правила
  одного дня); `World::restart()` возвращает старт.
- **Темп** (`view/pace.h`) — реальное время, поэтому вне симуляции (`mc_sim`), мира не знает: скорость 1–5 и пауза;
  решает только, сколько дней пройдёт. Скорости 1–4 — месяц за 60, 30, 15 и 7 секунд (набежавшие дни — одним вызовом);
  скорость 5 — как позволяет CPU: по дню, пока не истёк бюджет кадра (`Pace::kFrameBudget`, 8 мс), но минимум один. Кадр длиннее `Pace::kMaxFrame` (0.25 с) на скоростях 1–4 считается таким, чтобы не сыпать днями после
  затыка. Новая партия начинается на паузе, скорость 3.
- **Кто кого зовёт.** `Shell::frame` → `Pace::advance(dt, run)` → `World::advance_days(n)`. `Pace` хранится в `Shell`;
  вне фазы `playing` (`Session::playing()`) время стоит и кнопки темпа ничего не делают. Дни идут до отрисовки карты
  и UI в том же кадре. `mapcraft_sim` зовёт ту же `World::advance_days`.
- **Тик.** День `advance_days`: сначала команды дня (`run_commands`), потом `tick_day` — марш армий и `++day_`.
  Правила дня пока дешёвые, поэтому скорость 5 за кадр делает очень много дней. Счётчик дней — `u32` (около 12 млн
  лет).
