# Игровые данные (`data/`)

Содержимое игры — CSV-файлы, а не C++. Движок знает только схему; файлы задают, что именно существует.
`mapcraft_editor` пишет те же файлы, которые читает игра. Геометрия карты живёт отдельно, в `build/map/world.mcmap`.
«Истории» как в EU4 нет: одна дата старта (зашита в `game/calendar.h`, не в `data/`).

Данные в `data/` черновые, заполняет их пользователь в `mapcraft_editor`.

Экономика — EU3-lite (docs/ECONOMY.md, план); из правил есть казна, налог, перепись и ползунки бюджета («Казна»
ниже). У провинции — товар (trade good), `base_tax` и население; рынки регионов стали торговыми узлами (trade nodes в
смысле центров торговли EU3, без графа между узлами; правила — срез M14, docs/ECONOMY.md, «Торговые узлы»).

## Файлы
- Формат: CSV UTF-8, первая строка — заголовок.
- Ссылки между файлами — только по строковым ключам: латиница, `snake_case`; у стран — тег из трёх символов
  (заглавные латинские буквы или цифры).
- Номера стран и записей списков существуют только в памяти: их раздаёт загрузчик по порядку строк. Провинции —
  исключение: их номер — `id` карты.
- Цвет записывается как `#RRGGBB` и обязателен; в остальных колонках пустая ячейка значит «не задано».

| Файл | Колонки | Что |
|---|---|---|
| `common/terrain.csv` | key, name, color, movement_cost, attacker_penalty | логический terrain провинций (не вид карты); ставится руками в редакторе; `movement_cost` — во сколько раз дольше шаг в провинцию с ним, чем на равнину (1), > 0 («Движение армий»); `attacker_penalty` — минус к кубику атакующего в провинции с ним, целое 0..9 (защита местности EU4; решение пользователя: лес и холмы 1, горы 2; «Бой») |
| `common/biomes.csv` | key, name, color, density, minecraft_biome, top, side, under, deep, shore, snow_top, snow_side, snow_line, trees, tree_density, tree_line, village | биомы вида карты (см. ниже); не игровые данные, редактор его не правит |
| `common/countries.csv` | tag, name, adjective, color | определения стран; `adjective` — для частей, отрезанных от столицы, по умолчанию = name |
| `common/goods.csv` | key, name, color, price, icon | товары (набор — пользователя, растёт строками: без фабрик и рецептов, cattle — и мясо, и кожа); `price` — базовая цена товара (base price EU3/EU4) в изумрудах за единицу производства, > 0 (у изумруда всегда 1); по ней продаётся производство («Казна»), потом от неё — мировая цена, которую будут менять модификаторы и события; `icon` — предмет Майнкрафта для UI (M13), пока не читается |
| `common/trade_nodes.csv` | key, name, color | торговые узлы; узел — из целых регионов (`setup/regions.csv`); необязателен; правил узлов пока нет (M14) |
| `common/regiment_types.csv` | key, name, category, maneuver, off_fire, def_fire, off_shock, def_shock, off_morale, def_morale, cost | типы полков — юниты (как Latin Knights в EU4); `category` — infantry, cavalry или artillery; `maneuver` — манёвр юнита EU4, дальность удара вбок (фланг; пехота 1, конница 2); пипсы атаки и защиты огня, натиска и морали — целые 0–255 («Бой»); `cost` — цена найма полка в изумрудах, > 0 (EU3: пехота 9, конница 21, артиллерия 30), от неё содержание («Содержание армии»); необязателен (без него — без полков) |
| `common/defines.csv` | key, value | константы боя (`NDefines::NMilitary` EU4), каждая обязательна, по строке: `days_per_phase`, `dice_sides`, `cannot_retreat_days`, `overrun_factor`, `overrun_factor_cannot_leave`, `max_combat_width` (≤ 40) — целые ≥ 1; `leader_max_pips` (EU4 6), `back_line_reinforce_speed` (EU4 2), `river_crossing_penalty` (минус к кубику атакующего за переправу через реку, 1) — целые ≥ 1; `recovery_own_land`, `recovery_neutral_land`, `recovery_enemy_land`, `recovery_retreating` (доли макс. морали за месяц вне боя: 0.2, 0.15, 0.1, 0.05; «Восстановление») — десятичные; `war_length_damage`, `daily_morale_damage`, `reserve_daily_morale_damage`, `front_line_modifier`, `back_line_modifier` (EU4 0.5), `back_line_morale_damage_taken` (0.4), `back_line_strength_damage_taken` (0) — десятичные («Бой»); осада (`NMilitary` EU4, «Осада и оккупация»): целые ≥ 1 — `days_per_siege_phase` 30, `siege_dice_sides` 14, `siege_win` 20, `max_breach` 3, `siege_memory` 11, `siege_bonus_supplies_shortage` 1, `siege_bonus_food_shortage` 2, `siege_bonus_water_shortage` 3, `siege_bonus_defenders_desert` 2, `siege_garrison_surrender` 100, `garrison_size` 1000, `siege_min_men` 1000 (решение пользователя); целые ≥ 0 — `capital_fort_level` 1, `siege_unblockaded_penalty` 2, `garrison_after_capture` 100; десятичные — `siege_memory_scaled` 0.5, `siege_disease_impact` 0.05, `siege_force_needed_multiplier` 3, `garrison_growth` 0.05; война и мир (`NDiplomacy`/`NMilitary` EU4, «Война», `WarDefines`): целые ≥ 1 — `max_warscore` 100, `warscore_max_from_battles` 40, `truce_years` 5; десятичные — `province_value_base` 5, `province_value_cap` 30 (`AE_PROVINCE_CAP`), `capital_value_mult` 1.2, `fort_per_dev_ratio` 50; экономика (EU3, «Казна», «Содержание армии», `EconomyDefines`; вид `real` — десятичное в `double`, для ставок и долей, которые экономика считает во `float`): `real` — `capital_tax` 2, `census_core` 1, `census_no_core` 0.1, `treasury_inflation` 1, `production_base` 0.99, `force_limit_base` 6, `force_limit_per_base_tax` 0.25, `land_maintenance` 0.025, `force_limit_extra_cost` 1; целые ≥ 0 — стартовые доли ползунков бюджета `budget_army`, `budget_production`, `budget_government`, `budget_stability` 25 и `budget_treasury` 0 (решение пользователя), в сумме ровно 100; целые ≥ 1 — `population_per_unit` 100000, `base_tax_per_unit` 20, `maintenance_min` 50 и `maintenance_start` 100 (`maintenance_min` ≤ `maintenance_start` ≤ 100); десятичное `Fixed` — `min_maintenance_morale` 0.2 |
| `common/modifiers.csv` | key, name, modifier, value | наборы модификаторов — источники («Модификаторы» ниже): строка на пару «набор — модификатор»; `key` — набор, `name` — имя для людей (на любой строке набора, где есть — одинаковое; по умолчанию key), `modifier` — модификатор из списка кода, в наборе один раз, `value` — число (может быть отрицательным); набор `base` есть у каждой страны (base_values EU4); необязателен |
| `setup/provinces.csv` | id, name, owner, controller, cores, terrain, good, base_tax, population, fort | провинции суши на старте (docs/ECONOMY.md, «Провинция») |
| `setup/regions.csv` | region, name, trade_node | регион карты (номер из `regions.csv` карты) → торговый узел; пусто — без узла |
| `setup/countries.csv` | tag, capital, modifiers | страны на старте: столица (id провинции); `modifiers` — ключи наборов `common/modifiers.csv` через пробел (`base` — нельзя, он у всех) |
| `setup/armies.csv` | army, province, owner | армии на старте (только сухопутные): `army` — номер в файле, для `regiments.csv` и `leaders.csv`; `province` — провинция суши; имени нет (имя по слоту, «1st Army»); необязателен |
| `setup/regiments.csv` | army, type, strength | полки армий: `army` — номер из `armies.csv`, `type` — ключ `regiment_types.csv`, `strength` — люди, целое (полный полк 1000); мораль на старте полная — макс. мораль страны-владельца армии («Модификаторы»); необязателен |
| `setup/leaders.csv` | leader, army, owner, fire, shock, maneuver, siege | генералы на старте (адмиралов нет): `leader` — номер в файле; `army` — номер из `armies.csv` той же страны, пусто — без армии; у армии не больше одного; пипсы огня, натиска, манёвра и осады — целые 0…`leader_max_pips`; имени нет, как у армий; в редакторе — у армии («Add general», пипсы, «x»); необязателен («Бой», «Осада и оккупация») |

Подробности `common/biomes.csv` (читают инструменты карты и игра при запуске, docs/RENDER.md «Облик блоков»):
- `color` — цвет биома в `biome.png`; `density` — плотность провинций при генерации карты (1 — обычная, меньше —
  провинции крупнее);
- `minecraft_biome` — ванильный биом (`data/minecraft/worldgen/biome/<имя>.json` в jar), чьи температура, осадки и
  цвета дают оттенок травы и воды;
- блоки — имена текстур `assets/minecraft/textures/block/<имя>.png` из jar: `top` — верх, `side` — бок верхнего блока,
  `under` — бок следующих трёх, `deep` — глубже, `shore` — верх и бок берега (суша на блок выше моря или озера);
- `snow_line` — высота ступени (0–16, как `height` в корневом `provinces.csv` карты), с которой верх — `snow_top`, бок верхнего блока —
  `snow_side`; пусто — снега нет, тогда `snow_top` и `snow_side` можно не заполнять;
- `trees` — деревья: имена configured feature из jar (`data/minecraft/worldgen/configured_feature/<имя>.json`)
  через пробел, повтор — больший вес; поддержаны деревья с прямым и раздвоенным стволом (листва blob, spruce,
  acacia), столбики блоков (кактус) и одиночные блоки (сухой куст); `tree_density` — доля блоков карты с деревом (0–1, не
  больше дерева на блок); `tree_line` — ступень, с которой деревья не растут (пусто — растут везде);
- `village` — стиль домиков-городов (деревни Майнкрафта): `plains`, `desert`, `savanna`, `taiga`, `snowy`; выше
  `snow_line` биома — всегда `snowy`;
- биом, который есть в `world.mcmap`, обязан быть в таблице (ключ — `key`); правка блоков и оттенков видна после
  перезапуска, без пересборки карты; новый биом или новый `color` — правка `biome.png` и `bake.py`.

Флаги стран — `<TAG>.png` в папке `assets/flags` (путь задаётся при сборке, `MC_DEFAULT_FLAGS`; в репозитории папки
нет, картинки в git не идут). Файл необязателен: без него флаг — квадрат цвета страны. Решение пользователя на будущее —
флаги-баннеры с узорами (данные, не арт; docs/UI.md).

Подробности `setup/provinces.csv`:
- `id` — номер провинции карты;
- `name` нужен только человеку и для diff, загрузчик его не читает. Имя провинции живёт в двух местах: корневой
  `provinces.csv` карты (из него запекаются надписи) и эта колонка — переименовывать по id в обоих;
- `cores` — теги через пробел;
- `good` — товар провинции, ключ из `common/goods.csv`. Обязателен каждой провинции суши: без него — предупреждение
  загрузки и `--check` (не ошибка: у провинции суши без строки, новой на карте, товара нет, пока его не поставит
  редактор). Товар и terrain ставит пользователь руками: код не ограничивает и не подсказывает, что где может быть;
- `base_tax` и `population` — числа ≥ 0, пусто — 0 (смысл — docs/ECONOMY.md, «Провинция»);
- `fort` — уровень крепости, целое ≥ 0, пусто — 0 (как в EU4: замок 2, бастион 4, звёздная 6, крепость 8; столица
  сверх него получает `capital_fort_level`; «Осада и оккупация»). Ставит пользователь в редакторе (поле «Fort»).

`trade_nodes.csv` и `modifiers.csv` необязательны; обязательны `terrain.csv`, `goods.csv` (товар у провинции обязателен) и
`countries.csv`, `defines.csv` (константы боя, войны и мира).

Столица страны — `capital` в `setup/countries.csv`; без неё (или если провинция не своя) столицей считается первая
провинция страны, наименьший id (`seat`, `game/countries.h`).

Провинция без владельца допустима. Морских строк пока нет.

Номера провинций в `data/setup` — это id карты. **Ссылка на провинцию** в `data/setup` — колонка `id` в
`provinces.csv`, `capital` в `countries.csv`, а в любом другом файле — колонка `province` (так и называть её в новых
файлах). Ссылка на регион — колонка `region`, номер региона карты (1-based, `PREG`): номера регионов при правке
провинций не меняются. Перенумерация карты (`edit_provinces.py sync-lakes`, когда удаляется озеро) переписывает именно эти колонки
на новые id (`SETUP_COLUMNS` в скрипте), строки `provinces.csv` — в новом порядке. Строка удалённой провинции в
`provinces.csv` выбрасывается; любая другая ссылка на неё останавливает правку до записи файлов.

**Проверка при загрузке.** Неизвестный ключ или тег, повтор, id не суши или плохое число — это ошибка с файлом и
строкой, а не тихий ноль. Предупреждения (лог, `mapcraft_editor --check` и панель «Countries» редактора) — то, через что
проходит правка:
- столица вне владений своей страны;
- дисциплина, макс. мораль, тактика или ширина фронта страны не больше 0;
- когда торговые узлы есть: регион без узла и узел без регионов.

Проверить данные без окна: `mapcraft_editor --check`.

## В памяти (`code/src/game/game_data.h`)
- **Содержимое и состояние — разные типы.**
  - `Content` — справочники и `CountryDefinitions` (тег упакован в `u32`, имя, прилагательное, цвет). Все строки
    живут только здесь; после загрузки не меняется.
  - `WorldState` — столбцы: `Provinces`, `Regions` (торговый узел региона), `Balances` (деньги: счета стран,
    «Деньги»), `CountryStates` (столица, наборы модификаторов, ползунки бюджета, инфляция,
    ползунок содержания) с тем же индексом, что у стран, и таблицы сущностей `Armies`,
    `Regiments` (ниже); бои `Battles` — слоты структур `Battle`, не столбцы («Бой»); войны `Wars` и осады `Sieges` —
    слоты столбцов («Война», «Осада и оккупация»). Симуляция меняет только его.
    Столбцы заданы списками (ниже).
- **Метки** (`game/game_data.h`, у каждой структуры): **сохраняется** — `WorldState` и его части, то, что меняют дни
  и что попадёт в сейв; **контент** — `Content` и его части, неизменны после загрузки `data/common` и карты; **кэш** —
  рабочие данные правил, после загрузки и `restart` строится из двух первых, не сохраняется: `Cache` в `GameData`
  (суммы модификаторов стран и кто с кем воюет, перестраивает `GameData::rebuild_cache`) и кэши самих правил (граф марша — `Movement`,
  бой — `Combat` в `World`). Размеры (`count`, `core_words`) — ни то, ни другое: следуют из контента и карты. Дата (`World::day`) и
  `seed` мира тоже сохраняются, но лежат в `World`.
- **Списки столбцов (X-macro).** У каждой таблицы `WorldState` рядом со структурой — свой список
  (`MC_PROVINCE_COLUMNS`, `MC_REGION_COLUMNS`, `MC_BALANCE_COLUMNS`, `MC_COUNTRY_COLUMNS`): строка
  `X(таблица, тип, имя, старт)` на столбец, в порядке сохранения. Из списка раскрываются поля, `resize`,
  `for_each_saved` и чтение-запись `data/setup`; новый столбец — одна строка. Старт столбца:
  - `runtime` — 0 на старте, дальше меняет только игра (`money.cash`);
  - `setup("колонка", разбор)` — из `data/setup`, редактор пишет обратно; разбор: `country` (тег, пусто — нет; `u16`),
    `key(&Content::список)` (ключ справочника, пусто — нет; `u8`), `number` (число ≥ 0, пусто — 0; `float`), `whole` (целое ≥ 0, пусто — 0; `i32` или `u8` — до 255). Тип
    столбца, который не подходит разбору, не компилируется. Колонки нет в файле — ошибка загрузки;
  - `by_hand` — из `data/setup`, но читает и пишет свой код `GameData` (столица и провинция армии — провинция суши,
    армия полка — номер из `armies.csv`);
  - `derived` — не в `data/setup`: `GameData` ставит при загрузке из других столбцов (мораль полка — полная,
    гарнизон провинции — полный; ползунки бюджета и содержания — из `defines.csv`).
  Вне списков, явно: размеры (`count`, `core_words`, `modifier_words`), битовые матрицы коров и наборов
  модификаторов стран, маски живых слотов, маска отступающих армий (`armies.retreating`) и бои (`battles.list`). Ключ строки (`id`, `region`, `tag`) и
  `name` для людей — тоже свой код каждого файла. Метки «сохраняется / контент / кэш» — у типа, не у столбца; у кэша
  свои структуры со своими списками, без `for_each_saved` (обход — `for_each_cached`, `game/modifiers.h`).
- **Порядок колонок `data/setup`** — какой был в файле при загрузке (`GameData::setup_layout`), `save_setup` его
  сохраняет; колонки, которых в файле не было (файла не было), идут в конец: сначала свои, потом из списка.
  Колонки, которых игра не знает, при сохранении пропадают.
- **Список сохраняемого** — `game/saved_state.h`, `for_each_saved`: каждый столбец и число `WorldState` под
  стабильным именем (`provinces.owner`, `regions.trade_node`…), в одном порядке, столбцы целиком с дополнением:
  столбцы списков, коры — после столбцов провинций, наборы модификаторов (`countries.modifiers`) — после
  столбцов стран; бои — байтами структуры `Battle` (без выравнивающих дыр: `has_unique_object_representations`), в
  дампе — по полям; у таблиц слотов — только занятая часть (слоты до конца слова маски
  с последним живым, `used_slots`; остальное нулевое), иначе дамп и сумма каждый день шли бы по 65 тысячам пустых слотов. По нему идут дамп и контрольная сумма `mapcraft_sim`, позже —
  сейв. `static_assert` на `sizeof(WorldState)` считает столбцы списков сам и ловит новое поле вне списков, которое
  забыли разметить и внести в `for_each_saved`.
- **Правки сценария.** `GameData::load` принимает `csv::Patch` (`mapcraft_sim`, docs/SIMULATION.md): поле файла
  `data/` меняется в тексте до разбора, поэтому проверки те же; правка мимо файла, строки или колонки — ошибка. Игра и
  редактор правок не передают.
- **Сущности — слоты** (`Armies`, `Regiments`, `Leaders`, `Battles`, `Wars`, `Sieges`; `game/armies.h`). Армии, полки, генералы, бои, войны и осады
  рождаются и гибнут,
  поэтому у таблицы постоянное число слотов (`kArmySlots` = 4096, `kRegimentSlots` = 65472 — потолок `u16` без
  последнего слова маски: бой зовёт полк «слот + 1», 0 — нет; больше — слоты `u32`; `kLeaderSlots` = 1024;
  `kBattleSlots` = 1024, бой — один на провинцию; `kWarSlots` = 256; `kSiegeSlots` = 1024, осада — одна на провинцию), маска живых слотов `alive` (`u64`) и выдача наименьшего свободного слота — порядок детерминирован, на рождение
  сущности память не выделяется (выделять в тике можно, но не на каждую сущность ежедневного прохода — CLAUDE.md,
  «Раскладка данных»). Освобождённый слот обнуляется по списку столбцов (бой — `Battle{}`, кроме поколения). Слоты берут и освобождают только функции `game/armies.h`
  (`create_army`, `destroy_army` — вместе с полками, но не с генералом, `add_regiment`, `remove_regiment`,
  `create_leader`, `destroy_leader`; маска — `take_slot`, `free_slot`, их зовут и `declare_war`, `game/war.h`, и осада,
  `game/occupation.h`); обход — `for_each_alive`
  по порядку слотов. Ссылка на армию извне (команда, бот, UI) — `ArmyRef` (слот + поколение): `generation` растёт
  при каждом освобождении слота, и старая ссылка больше не разрешается (`resolve`). Полк ссылается на армию просто
  слотом. Генерал — своя сущность: переживает армию; армия зовёт его `armies.leader` (слот + 1, 0 — нет), гибель
  армии оставляет генерала без армии. Имя армии — не данные: порядковый номер слота («1st Army», `ui/army_name.h`). При загрузке армии
  занимают слоты по порядку файла; `save_setup` пишет живые армии в порядке слотов с номерами 1, 2, …
  Марш армии — столбцы `next`, `destination`, `progress` (`runtime`, «Движение армий»).
- **Индексы.** Провинция и страна — `u16`, 0 = нет; провинции 1..N, как в карте. Terrain, товар, торговый
  узел и тип полка — `u8`, 0 = нет, поэтому в каждом списке не больше 255 записей (проверяется).
- **Раскладка.** Каждое поле — свой столбец длиной N+1, дополненной до кратной 16, с выравниванием 64 байта
  (`Column<T>`, `AlignedAllocator`). Цикл по провинциям идёт по столбцу подряд.
- **Числа — `float`**; балансы и требования — `i64` (docs/ECONOMY.md, «Деньги в i64»); модификаторы и бой — `Fixed`
  (`core/fixed.h`: `i32`, 1000 = 1.0, усечение после каждой операции, как `CFixedPoint` EU4): мораль полка, его сила
  в людях (`i32`), значения и суммы модификаторов. Симуляция
  строго детерминирована (мультиплеер будет): правила — docs/SIMULATION.md, «Детерминизм».
- **Коры** — битовая матрица провинция × страна (по `u64`-слову на 64 страны); наборы модификаторов стран — так же,
  страна × набор.
- **Владение:**
  - в игре `GameData` принадлежит `game/World`, наружу он отдаёт только `const`;
  - карта (`App::set_game`) и UI только читают;
  - редактор держит свой `GameData` и правит только `state`; undo хранит снимки `WorldState` (64 шага); после
    каждой правки, undo и redo — `rebuild_cache`.

## Модификаторы (`game/modifiers.h`)
Общий механизм правил EU3 (docs/SIMULATION.md, «Модификаторы»): источник → модификатор → значение.
- **Модификаторы** — список кода `MC_COUNTRY_MODIFIERS` (`game/game_data.h`), строка `X(имя)` на модификатор; имя —
  его ключ в данных. Сейчас: `discipline` (дисциплина, 1 = 100%), `base_morale` (база макс. морали полков, число;
  в EU4 её даёт технология), `land_morale` (доля к базе, «мораль армий» EU4: +0.1 — +10%), `military_tactics`
  (тактика EU4), `combat_width` (ширина фронта, целая), `infantry_fire`, `infantry_shock`, `cavalry_fire`,
  `cavalry_shock`, `artillery_fire`, `artillery_shock` (урон оружия категории в фазе — числа техов EU4);
  осада: `siege_ability` и `fort_defence` (доли: короче фазы своих осад и длиннее — осад своих крепостей),
  `artillery_levels_available_vs_fort` (больше всего, что даёт артиллерия осаде, целое; EU4 5), `highest_fort`
  (высший уровень крепости, который страна может строить, целое: замок 2; теха потом поднимет). Новый модификатор —
  строка списка и формула, которая его читает.
- **Числа — `Fixed`** (`core/fixed.h`): значение из файла разбирается точно (до трёх знаков после точки), суммы —
  целые сложения, как `CFixedPoint` EU4.
- **Источник — набор** (`common/modifiers.csv`, контент `ModifierBundles`): у набора значения по модификаторам,
  столбец на модификатор по наборам. Набор `base` есть у каждой страны и задаёт базу — накопленные числа военной техи 7 EU4, первой с
  артиллерией (решение пользователя 27.11.2026; прежде — теха 3), кроме ширины (решение 26.11.2026): дисциплина 1,
  `base_morale` 3, `military_tactics` 1.25 (0.5 + теха), `combat_width` 15 (в EU4 на техе 7 — 24), `infantry_fire`
  0.55, `infantry_shock` 0.95, `cavalry_shock` 1.2, `artillery_fire` 1, `artillery_shock` 0.05,
  `artillery_levels_available_vs_fort` 5, `highest_fort` 2; технологии потом
  прибавят к суммам;
  остальные — у страны в наборе `countries.modifiers` (сохраняется: потом его будут менять форма правления, идеи,
  события). Модификаторов провинций пока нет: их список и суммы придут с первым правилом, которое их читает.
- **Значения складываются** (решение пользователя 26.11.2026, как EU4 и Divine Wind): сумма страны по модификатору —
  значение `base` плюс значения её наборов, по порядку наборов в файле; что значит сумма (число или доля, где 0.1 —
  +10%), решает формула, которая её читает.
- **Суммы — кэш** `CountryModifiers` (`Cache` в `GameData`): столбец на модификатор по странам; строит
  `sum_country_modifiers` проходом по странам на каждый набор, без ветвлений внутри (маска, не `if`); перестраивается после загрузки,
  `restart` и правки в редакторе (`rebuild_cache`). В тике сумм пока не меняет ничего.
- **Правила читают только формулы** `game/modifiers.h`: `discipline`; `max_morale` = `base_morale` × (1 +
  `land_morale`) (у модификатора и формулы разные имена, чтобы база не путалась с итогом); `tactics` =
  `military_tactics` × `discipline` (`GetMilitaryTactics` EU4: на неё делится урон по полкам страны — так дисциплина
  цели снижает получаемый урон); `combat_width`; `weapon` (категория, фаза); `siege_ability`, `fort_defence`,
  `artillery_vs_fort`, `highest_fort`. Их читают бой, осада, полная мораль полка (загрузка и новый полк в редакторе),
  плашка и подсказка армии и провинции.
- Предупреждение загрузки: дисциплина, макс. мораль, тактика или ширина страны не больше 0 (нет набора `base`).
- `mapcraft_sim` пишет суммы в `cache.csv` папки прогона и сверяет кэши двух прогонов в конце (docs/SIMULATION.md).
- Правка сценария (`csv::Patch`) находит строку по первой колонке, а у набора их несколько: значения
  `modifiers.csv` сценарием пока не поправить.

## Бой (`game/combat.h`)
Сухопутный бой EU4 1.37.5 день за днём в порядке операций eu4.exe, как его воспроизводит BattleSim
(`CCombat::DailyUpdate`, `FireAt`, `ArrangeBattleField`, `ReorganizeTroops`, `CheckOverrun`, `WillLose`), в `Fixed`.
Сейчас — база (решение пользователя 26.11.2026): фазы, кубики, пипсы, мораль, дисциплина, тактика, расстановка, цели
по манёвру, стеквайп, отступление; генералы и артиллерия во второй линии (27.11.2026; BattleSim её не делает —
по декомпиляции eu4.exe, `C:\Dev\Projects\eu4\archeologyEU4\UtilityAI\evidence`, адреса в `game/combat.cpp`);
местность и переправы (28.11.2026). Ещё нет: нехватка поддержки конницы, combat
ability и модификаторы урона (все 0), прорыв (`*_BREAKTHROUGH`, в EU4 0). Мораль вне боя — «Восстановление». Известное
расхождение: EU4 при расстановке сортирует группы `CUnitCombatComparator`, он не разобран; у нас — порядок резерва,
как в BattleSim.
- **Враги** — армии стран, которые воюют («Война»); армии стран в мире стоят в одной провинции без боя. У боя две
  стороны, по стране. Пара: страна первой (по слоту) армии, стоявшей в провинции до сегодня, у которой здесь есть
  враг (иначе первой такой), и первая страна, воюющая с ней и пришедшая сегодня (иначе первая воюющая с ней).
  Атакует пришедшая, если другая стояла здесь до сегодня; иначе (обе стояли, когда началась война, или обе пришли
  сегодня) — объявившая их войну (решение пользователя 28.11.2026). Третья страна ждёт конца боя. Армии двух стран боя, входящие в провинцию, вступают в
  него (`TryToJoin`): полки — в конец резерва своей стороны (`AddUnit`), с той моралью, что есть. Вступившая армия
  останавливает марш; приказ армии в бою и отступающей отклоняется.
- **День** (`World::tick_day`: команды → марш → бой): конец отступлений, которые пришли; новые бои и вступления; у
  каждого боя по порядку слотов — до выстрелов: длительность +1; в первый день кубики, расстановка
  (`ArrangeBattleField`), заполнение фронта без второй линии и стеквайп ×10 до первого выстрела; раз в `days_per_phase` дней — новые
  кубики и смена фазы огонь ↔ натиск; командующие и глобальные модификаторы сторон; перестроение обеих сторон (`ReorganizeTroops`); выстрелы атакующего, потом
  защитника, урон копится. Потом урон дня ложится на все полки разом плотным проходом без ветвлений (`ApplyDamage`),
  полки без людей освобождают слот (`DeleteEmptySubUnits`), армии без полков гибнут; потом у каждого боя — исход
  (`WillLose` атакующего первым, `CombatEnds`) или стеквайп ×2 до `cannot_retreat_days`.
- **Генералы** (`CalcHighestCommander`, `DetermineGlobalModifiers`; каждый день после кубиков): командующий стороны —
  генерал с наибольшим огонь + натиск + 1 среди её армий в бою; при равенстве — армии, вступившей раньше
  (`armies.joined` — день боя при вступлении), потом меньший слот: EU4 держит армии стороны в порядке вступления.
  Глобальный модификатор стороны — пипсы её командующего в текущей фазе сверх пипсов командующего врага, не меньше 0
  (без командующего — 0 пипсов); прибавляется к кубику каждого выстрела.
  Назначать генерала армии в игре — с UI (решение пользователя 27.11.2026: на своей или нейтральной земле можно, на
  вражеской неоккупированной — нельзя); пока генералы приставлены армиям на старте (`setup/leaders.csv`).
- **Местность и переправа** (решение пользователя 28.11.2026; `DetermineGlobalModifiers`, `GetCrossingType`): из
  глобального модификатора атакующего вычитается `attacker_penalty` местности провинции боя (`provinces.terrain`,
  `terrain.csv`) и переправа боя. Переправа (`Battle::crossing`) ставится при начале боя: `river_crossing_penalty`
  (`defines.csv`), если армия, сделавшая страну атакующим, пришла сегодня шагом, путь марша которого пересекает реку
  (`Movement::crossed_river_today`, docs/MAPFORMAT.md, `MPTR`); иначе 0; вступающие позже армии её не меняют.
  Проливов нет и не будет. Переправа снимается целиком, пока манёвр командующего атакующего строго больше манёвра
  командующего защитника (без командующего — 0); местность — никогда. Модификатор может уйти ниже 0: выстрел и так
  обрезает `x` до 0..21. Подсказка провинции в игре показывает оба минуса.
- **Артиллерия — вторая линия** (`BattleSide::back`, места `kPlaceBack` + позиция):
  - расстановка: пушки — во вторую линию от центра наружу, не больше ширины; после обычной расстановки фронта
    оставшаяся пехота встаёт только перед пушками; в резерв — пехота, конница, потом лишние пушки;
  - перестроение: сломанные уходят из обеих линий; пустую позицию фронта занимает первый годный полк резерва, а без
    него (не в первый день) — пушка за ней, без неё — пушка из резерва, если напротив годный враг
    (`ReinforceFrontLineAtIndex`); потом во вторую линию — не больше `back_line_reinforce_speed` + манёвр командующего
    / 2 пушек в день (не меньше 1), сначала за позициями, где стоят оба фронта, потом где один, потом любые
    (`ReinforceBackLine`); сдвиг к центру — только фронт;
  - выстрелы: в пределах ширины, от центра, на каждой позиции стреляет фронт (дальность `front_line_modifier`) и
    пушка за ним (`back_line_modifier`); за пределами ширины обе линии уходят в резерв; обе линии теряют мораль линии;
  - в выстреле: пушка за целью даёт ей половину своих защитных пипсов фазы (к пипсам морали — половину защиты
    морали + фазы); пушка, по которой бьют во фронте, получает двойную базу людей; вторая линия врага на позиции
    *стрелка* получает `back_line_morale_damage_taken` урона морали и `back_line_strength_damage_taken` людей;
  - оружие артиллерии — `artillery_fire` / `artillery_shock`.
- **Выстрел** (`FireAt`): `x = clamp(пипсы фазы + глобальный модификатор + кубик + 2, 0, 21)`, база `25 + 25x`; люди: × сила × дисциплина ×
  `front_line_modifier` / тактика цели × оружие × 0.2 × (ранги/4 при ударе во фланг) × (1 + `war_length_damage` ×
  день); мораль: макс. мораль стрелка / 2.7 × база по пипсам морали и фазы, те же множители без 0.2 и рангов.
  Множители, которые сейчас 1 (combat ability, урон нанесённый и полученный, урон морали), опущены: умножение на 1.000
  ничего не меняет. Пример вики (кубик 5, теха 3) — 28 человек за выстрел. Дальность — линии стрелка.
- **Цель и манёвр**: полк напротив, иначе первый годный слева направо в пределах манёвра, иначе (если напротив пусто)
  любой в пределах; манёвр = `maneuver` типа × 100/50/25/0% по рангам (сила > 750, 500, 250 людей), не меньше 1.
- **Ширина** — наибольший `combat_width` двух стран, не больше `max_combat_width`; линия — 41 позиция (0..40), обход —
  от центра (21) наружу.
- **Конец**: проигравший отступает, если победитель не в `overrun_factor` раз сильнее (а пока бой нельзя покинуть —
  не вдвое): тогда стёрт, армии гибнут. Победитель получает мораль не ниже макс. × min(0.75, 1.25 × вошедшие люди
  проигравшего / победителя) (`GiveEndOfCombatMoraleBoost`).
- **Отступление** (решение пользователя): в свою провинцию, которую страна и контролирует (не занятую врагом), самую
  дальнюю от провинции боя по пути марша; таких нет — в ближайшую без армий стран, воюющих с ней; равенство — меньший
  id. Пока идёт — бит `armies.retreating`: марш не перехватить, боёв и осад армия не начинает и в них не вступает; бит
  снимается, когда марш окончен. Запрет отступать во вражескую — с дипломатией (M11).
- **Кубики** — `random(seed, день, бой (слот | поколение << 16), назначение) % dice_sides` (`core/random.h`).
- **Раскладка** (решение пользователя 27.11.2026, по четырём вопросам — docs/SIMULATION.md, «Раскладка данных»): боёв
  единицы, день боя трогает все его поля, логика ветвистая — поэтому бой — структура `Battle` в слоте, как у
  BattleSim; полки и армии остаются столбцами: их проходят и другие правила по одному-двум полям.
- **Состояние** (сохраняется): `Battles` — слоты `Battle` (`game/game_data.h`): провинция, длительность, день фазы,
  фаза, поколение, люди, вошедшие на каждую сторону, переправа атакующего, и две стороны `BattleSide` — страна, кубик, линии `front` и
  `back` (по 41 позиции, полк — слот + 1, 0 — пусто) и резерв — двусвязный список через `regiments.reserve_prev` и `reserve_next`
  (`reserve_first`, `reserve_last`; порядок EU4: вошедший — в конец, в линию идёт первый годный); `armies.battle`
  (слот боя + 1), `armies.side` (0 атакующий, 1 защитник), `armies.joined` и маска `armies.retreating`; `regiments.place` (не в бою,
  позиция линии + 1, резерв, «ушёл из линий» — сломан, но в армии). Место полка и линия/резерв боя всегда согласованы:
  полк меняет место только вместе с ними.
- **Рабочие данные** `Combat` (в `World`, вместимость — при загрузке, потом переиспользуются; только на день,
  поэтому загрузка и рестарт ничего не меняют): армии по провинциям (CSR, сортировка подсчётом), число полков армий,
  урон дня по слотам полков, день боя `BattleDay` — ширина и у сторон командующий, глобальный модификатор, числа страны
  (дисциплина, тактика, макс. мораль, оружие) и итоги (люди, мораль всех и годных).
- В игре: плашки армий стран, воюющих с игроком, красные, остальных чужих — нейтральные; подсказка провинции показывает бой (стороны, день, фаза,
  кубики) и пипсы генерала каждой армии. В `mapcraft_sim` — сценарии `battle`, `generals`, `artillery`, `crossing` и
  `crossing_plains` (в каждом DUM в день 0 объявляет войну NBR; docs/SIMULATION.md).

## Восстановление (`game/recovery.h`)
Вне боя армии восстанавливаются раз в месяц, на месячном тике («Время»; решение пользователя 28.11.2026: только
месячный тик, как в EU4). Полк армии не в бою получает долю макс. морали своей страны (`game/modifiers.h`), не
выше максимума; мораль выше максимума не срезается. Ползунок содержания ниже 100% ставит потолок ниже максимума
(«Содержание армии»): сначала мораль каждого полка страны срезается до него, потом восстанавливается только до него. Доля — по тому, где стоит армия (решение пользователя;
`defines.csv`):
- своя земля (страна армии владеет провинцией) — `recovery_own_land`, 0.2;
- ничья земля (нет владельца) или оккупированная (страна армии контролирует, но не владеет) — `recovery_neutral_land`,
  0.15;
- вражеская (владеет страна, воюющая со страной армии, и страна армии её не контролирует) — `recovery_enemy_land`,
  0.1; земля страны, с которой войны нет, — ничья по доле, 0.15;
- армия отступает (бит `armies.retreating`), где бы ни была, — `recovery_retreating`, 0.05.

Те же доли потом — для пополнения людей полков (M8). Раскладка: раз в месяц, поэтому просто — проход по армиям (доля
и максимум в рабочие столбцы `Recovery` по слотам армий), потом по полкам. В `mapcraft_sim` — сценарий `morale`,
помесячный ряд `armies.csv` (docs/SIMULATION.md).

## Война (`game/war.h`)
Война, военный счёт и мир (M7, шаги 1 и 3; решения пользователя 28.11.2026). Война — между двумя странами:
объявившей (атакующий) и той, кому объявлена (защитник); союзов и вассалов в войне нет (стороны — с дипломатией, M11).
Начинается командой «объявить войну» (`declare_war`) — без поводов и infamy; любая страна любой другой, если они ещё не
воюют и между ними нет перемирия; на старте войн нет. Кончается миром (`peace`, ниже) — после него перемирие.
- **Что значит война**: бой — только между воюющими («Бой»); отступающий не идёт в провинцию с армиями воюющих с ним;
  вражеская земля для морали — земля воюющей страны («Восстановление»); осаждают провинции воюющих («Осада и
  оккупация»). Ходить по земле стран без войны можно
  (военный доступ — M11).
- **Состояние** (сохраняется): `Wars` — слоты (`kWarSlots` = 256), столбцы `attacker`, `defender`, `start` (день
  начала), `battle_score` (Fixed: сумма очков боёв, «+» — атакующему, без потолка), `generation`, маска `alive`;
  `Truces` — слоты (`kTruceSlots` = 256): `first` < `second` (страны), `until` (первый день, когда можно снова объявить),
  маска `alive`; месячный тик освобождает истёкшие; без файла `setup`.
- **Кэш** `AtWar` (`Cache::at_war`): симметричная битовая матрица стран (слова `u64`), пересобирается из `Wars` после
  загрузки и рестарта (`GameData::rebuild_cache`), объявление ставит свой бит сразу; правила спрашивают `at_war(a, b)`.
- **Военный счёт** (`game/war_score.h`) — `CWar::GetWarScore` EU4 1.37.5 в его порядке и целой арифметике
  (`archeologyEU4/UtilityAI/research/PEACE.md`, адреса eu4.exe — в заголовке), из того, что есть: бои и оккупация; без
  блокады (флота нет) и тикающей цели войны (поводов нет до M11). Целое число, со стороны атакующего:
  - полная победа — ±`max_warscore`, когда одна сторона контролирует все провинции другой (сначала проверяется победа
    защитника, как в eu4.exe);
  - иначе `clamp(бои, ±max_warscore)` + оккупация атакующего − оккупация защитника, в пределах ±(`max_warscore` − 1);
  - **бои**: `battle_score` войны ÷ 1000 (усечение), в пределах ±`warscore_max_from_battles`; очки боя победителю
    (`CalculateBattleScore`) — `max(0.1, ⌊потери/1000⌋ / max(2·FL, 2·⌊потери/1000⌋) × warscore_max_from_battles/2)`, не
    больше 10 за бой; потери проигравшего — люди, с которыми он вступил (`Battle::joined`), минус стоящие в конце (при
    уничтожении — все). Начисляет `Combat::finish`;
  - **лимит армии FL** — лимит сил страны, целый («Содержание армии»);
  - **оккупация** (`GetOccupiedScore`): по каждой провинции врага, которую сторона контролирует, `ценность / сумма
    ценностей всех провинций врага × 100` (Fixed, сумма — целыми очками, как `_nTotalWarWorth`), итог усекается до
    целого;
  - **ценность провинции** (`GetWarValue`): `province_value_base` + min(`base_tax`, `province_value_cap`); у столицы
    владельца × `capital_value_mult`; без крепости (уровень < 1, «Осада и оккупация») — × 0.1, если у владельца ≥ 10
    крепостей, иначе × (4 − 3r)/10, r = min(1, крепости × `fort_per_dev_ratio` × 2 / развитие владельца), при
    развитии 0 — × 0.4; итог 1…100.
  Своего состояния у счёта нет: считается по запросу.
- **Мир** (`game/peace.h`) — команда `peace`: страна предлагает врагу передать ей его провинции или, без провинций,
  белый мир. Нельзя: не воюют, провинция не врага или дважды, все провинции врага (аннексии нет до M11). **Цена**
  провинции — её ценность как есть (стоимость договора EU4). **Ответ** — сразу, правилом мира (одинаково на всех
  машинах; пока ответить может только правило — и за игрока): требование принимается, если цена ≤ военного счёта
  предложившего; белый мир — если получатель проигрывает (его счёт < 0). «Желание мира» EU4 — в M12; бот сам мир
  не предлагает. Деньги — с казной (M8), вассалы и прочее — с дипломатией (M11).
- **При мире** (`make_peace`, по порядку): война кончается (слот, кэш); бои стран, которые больше не воюют, кончаются
  без победителя (`end_battle`: без отступления и очков); провинции каждой из двух под контролем другой возвращаются
  владельцам; переданные — победителю, вместе с контролем (коры не меняются); если отдана столица — она переезжает в
  провинцию проигравшего с наибольшим `base_tax` (при равенстве — меньший id); гарнизоны выше максимума своей крепости
  срезаются до него; осады, которые больше не могут быть (`may_besiege`), снимаются; перемирие на `truce_years` × 360
  дней. Армии остаются где стоят (военного доступа нет). Смена контролёра обнуляет прогресс осады провинции.
- **Перемирие** запрещает только объявить войну тому же.
- **В игре** — пока отладочно: окно «Dev» по F9 (docs/CODE.md, «Отладочное»): идущие войны и их счёт с разбивкой;
  у войн играемой страны — «Peace with …»: провинции врага с ценой галочками, цена и счёт, ответ, который даст враг,
  «Demand» и «White peace»; «Declare war» на каждую другую страну (при перемирии — его срок). Смена владельца
  перерисовывает цвета и названия карты (`App`). Настоящий UI — в своём срезе (M13).
- В `mapcraft_sim` — команды сценария `day N = DUM war NBR` и `day N = DUM peace NBR 476 473` (без провинций —
  белый мир); сценарии `war` (армии в мире стоят рядом без боя; в день объявления — бой, атакует объявивший),
  `peace` (отказ при счёте 0, отказ победителя от белого мира, требование двух провинций принято, перемирие не даёт
  объявить снова), `white_peace` (проигрывающий принимает белый мир); ряд `wars.csv` (docs/SIMULATION.md).

## Осада и оккупация (`game/occupation.h`)
Осада EU4 1.37.5 (`CSiegeCombat`: `TryToSiege`, `DailyUpdate`, `TickSiegePhase`, `CalcSiegeImpact`,
`GetArtilleryValue`, `GetDaysPerSiegePhase`, `GetMaxSiegeMemory` — декомпиляция в
`C:\Dev\Projects\eu4\archeologyEU4\UtilityAI\evidence`; вики EU4, «Land warfare», «Sieges»). Решение пользователя
28.11.2026: осада — в каждой провинции; без крепости — одна фаза (30 дней), с крепостью — полная осада EU4; осаждать
можно не меньше чем 1000 людьми (`siege_min_men`), даже где гарнизона нет; своя провинция, занятая врагом,
возвращается тоже осадой.
- **Контролёр** — `provinces.controller` (на старте — `setup/provinces.csv`). Меняет его только сдача крепости.
- **Крепость** — `provinces.fort` (`setup`, уровень EU4); уровень провинции = `fort` + `capital_fort_level`, если она
  — место правления своего владельца (`seat`, `game/countries.h`; EU4: столица всегда крепость уровня 1).
  Макс. гарнизон = уровень × `garrison_size`; гарнизон `provinces.garrison` (люди) на старте полный, каждый месяц вне
  осады растёт на `garrison_growth` от максимума (базовые 5% EU4; +1% за base manpower — с людскими ресурсами, M8).
- **Кто осаждает.** Страна, армии которой стоят в провинции (не идут маршем и не отступают), если там нет боя, у
  провинции есть владелец и контролёр, страна воюет с контролёром и либо владеет провинцией (возврат), либо воюет и с
  владельцем. Людей у этих армий вместе — не меньше `siege_men_needed`: `siege_min_men`, а у крепости с гарнизоном —
  не меньше `siege_force_needed_multiplier` × макс. гарнизона (EU4: 3000 на 1000 гарнизона). Осада начинается в тот
  день, когда условия сошлись, её дни идут со следующего. Если в провинции армии двух стран, которые могут осаждать,
  осаждает страна первой по слоту армии. Людей стало меньше нужного, армий не осталось, войны нет — осада кончается:
  её дни и бреши пропадают, прогресс остаётся у провинции и тает на 1 в день (вики EU4; в EU4 при нехватке людей
  осада стоит, у нас её нет — решение пользователя). Пока в провинции идёт бой, дни осады стоят (`DailyUpdate` EU4);
  армии в бою осаждать продолжают.
- **Фаза.** Каждый день осады — `days` + 1; при длине фазы — бросок и `days` = 0. Длина = `days_per_siege_phase` ×
  max(0.1, 1 + `fort_defence` контролёра − `siege_ability` осаждающего − разница `military_tactics` / 4, не больше
  ±0.5); `CalcTacticsDiff` (0x1402416b0): (тактика осаждающего − тактика контролёра) × 250 / 1000 с обрезкой, тактика
  стороны — военная теха плюс модификатор тактики, без дисциплины.
- **Бросок** — `random(seed, день, осада (слот | поколение << 16), 16) % siege_dice_sides + 1` (1–14) + удар. Удар
  (`CalcSiegeImpact`) без крепости — 0; с крепостью — прогресс + осада командующего + бреши + артиллерия + блокада −
  уровень + устаревание + 1 при гарнизоне меньше половины максимума:
  - командующий — генерал с наибольшим огонь + натиск + 1 среди осаждающих армий (равные — меньший слот армии, как
    `CalcHighestCommander`); прибавляются его пипсы `leaders.siege`;
  - артиллерия — люди артиллерийских полков осаждающих / 1000 / (уровень / 2 + 1), целое, не больше
    `artillery_levels_available_vs_fort` страны, не меньше 1 при любой артиллерии;
  - блокада — −`siege_unblockaded_penalty` у крепости с портом (`has_port`: точка порта карты); флотов нет, поэтому
    у каждой такой;
  - устаревание — (`highest_fort` осаждающего − max(уровень, 2)) / 2, не меньше 0.
- **Итог** (`TickSiegePhase`): гарнизон меньше `siege_garrison_surrender` — итог 99 (сдача; без крепости гарнизона нет,
  поэтому сдача на первой фазе). Выпала 1 и итог не сдача — болезнь: каждый полк осаждающих теряет
  `siege_disease_impact` людей. Иначе брешь, если артиллерия / 2 + бросок + устаревание / 2 ≥ `siege_dice_sides`,
  брешей меньше `max_breach` и итог не сдача: брешь + 1, прогресс + 2, гарнизон −5%. Иначе по итогу: ≤ 4 — ничего;
  меньше `siege_win` − 8 — нехватка припасов (прогресс + `siege_bonus_supplies_shortage`, гарнизон −1%); меньше − 6 —
  еды (+`siege_bonus_food_shortage`, −3%); меньше − 4 — воды (+`siege_bonus_water_shortage`, −5%); меньше `siege_win`
  — дезертирство (+`siege_bonus_defenders_desert`, −10%); иначе сдача. Прогресс не выше `siege_memory` +
  `siege_memory_scaled` × `highest_fort` (12 у замка).
- **Сдача**: контролёр — осаждающий (если он владелец — провинция освобождена), прогресс 0, гарнизон
  `garrison_after_capture` (EU4: 100), но не больше максимума; слот осады освобождается.
- **Состояние** (сохраняется): `Sieges` — слоты (`kSiegeSlots`), столбцы `province`, `country`, `days`, `phases`,
  `breaches`, `roll` и `result` последней фазы (`SiegeResult`), `generation`; у провинций `fort` (`setup`),
  `garrison` (`derived`) и `siege_progress` (`runtime`). Армии осады не помечены: это армии страны осады, стоящие в
  провинции.
- **Рабочие данные** `Occupation` (в `World`, вместимость — при загрузке, потом переиспользуются): порты, отметки дня (бой, осада, кандидат —
  счётчиком `stamp_`, не днём мира, поэтому рестарт их не путает), люди и артиллерия армий за день (проход по полкам),
  осаждающие каждой осады, места правления стран (месяц).
- **Зоны контроля не будет** (решение пользователя 28.11.2026: игра — EU3-lite; ЗК — кошмар для поиска пути, ИИ — позже):
  крепость не держит соседние провинции, марш через них свободен, контроль без крепости сам к владельцу не
  возвращается — только осадой.
- **Не сделано**: штурм, вылазка, бросок осады после выигранного боя, «осаждающий — всегда атакующий» в бою, истощение
  при осаде (M8), законсервированные крепости, оборонительность местности, вклад артиллерии
  (`artillery_levels_contribution`), армейская традиция за осаду, мораль гарнизона.
- **Исход фазы** — одна функция `siege_outcome` (бросок → итог, прогресс, потери гарнизона); её зовут и правило, и
  шансы `siege_chances`: сколько граней кубика дают каждый итог и сдачу (как подсказка осады EU4).
- **В игре**: подсказка провинции — «Occupied by …», уровень крепости и гарнизон, осада (страна, люди и сколько нужно,
  день фазы, прогресс, бреши, слагаемые удара, шанс взять на следующей фазе и шанс каждого итога, последний бросок).
  На карте — полосы оккупации цвета контролёра (docs/RENDER.md, «Режимы карты»). В редакторе — поле «Fort»
  провинции и пипс «siege» генерала.
- В `mapcraft_sim` — сценарий `siege` (docs/SIMULATION.md); ряды `sieges.csv` (начало, фазы, сдача и снятие осад) и
  `control.csv` (смены контролёра).

## Деньги (`core/money.h`, `game/economy/`)
- **Тип.** `Money` — `i64`, целые крупинки, 10⁶ на изумруд. Сумма считается во `float`/`double`, округляется до
  крупинок один раз (`to_grains`), и ровно это целое переходит со счёта на счёт. `to_emeralds` — только для показа.
- **Счета** — `Balances` в `WorldState`: один столбец `cash`, у каждой страны пять счетов (`Account`, в порядке
  ползунков): `army`, `production`, `government`, `stability` — вложения, и `treasury` — казна; номер счёта —
  `account(страна, вид)` = страна × 5 + вид (у страны 0 свои, не используются). На старте все 0 (`runtime`).
- **Пишет только `ledger`:** `mint` (доход из ничего), `mint_shares` (доход из ничего, разложенный по счетам целыми
  весами: каждому — целая часть доли без переполнения, остаток деления — счёту с наибольшим весом, первому из равных),
  `transfer` (точная сумма между счетами; не уходит в минус), `settle` — пакетный расчёт: каждый плательщик платит
  ровно своё, сумма делится между получателями по весу (каждому — целая часть доли), остаток деления — получателю с
  наибольшим весом (первому из равных), ни одна крупинка не теряется. Зовут его казна (`mint`, `mint_shares`);
  `transfer` и `settle` — пока никто. Деньги не замкнуты: проверки «сумма балансов = старт + добыто» нет. Счётчиков
  потоков по видам (`Flow`) пока нет: читать их некому, доход в окне считается той же формулой, что в тике.

## Казна (`game/economy/income.h`, `budget.h`)
Две системы денег EU3 (docs/ECONOMY.md, «Казна: две системы»; решения пользователя 28.11.2026):
- **Доход провинции** (`income.h`, формулы — общие для тика и UI): провинция платит владельцу, только пока он её
  контролирует (оккупированная не даёт никому ни налога, ни производства). База — `base_tax` + `capital_tax` (2),
  если это столица владельца (`seat`, `game/countries.h`). Налог за месяц — база / 12; перепись — база ×
  `census_core` (1) с кором владельца, × `census_no_core` (0.1) без.
- **Производство** (решения пользователя 28.11.2026): объём товара за год — EU3 In Nomine, `production_base` +
  население / `population_per_unit` + `base_tax` / `base_tax_per_unit` (0.99, 100 000, 20; при 5000 людей и
  `base_tax` 1 — 1.09). За месяц — объём / 12 × цена товара; цена — пока базовая `price` из `goods.csv` (мировой
  цены от предложения и спроса нет: без модификаторов она была бы постоянной; придёт с ними). Изумруд (товар
  `emerald`, золото EU3) — объём / 12 прямо деньгами, без цены; инфляции от золота пока нет. Эффективности
  производства и модификаторов пока нет (технологии, стабильность, ползунки внутренней политики — M9).
- Сумма страны — `double`, по провинциям в порядке id, отдельно налог, производство, золото и перепись
  (`world_income` — один проход для тика, `country_income` — для одной страны в UI и ряда, те же суммы), до крупинок
  округляется один раз.
- **Перепись** — 1 January (годовой тик, «Время»; первая — в году 2): `mint` в казну.
- **Месячный доход** (налог за месяц + производство + золото) в казну не идёт: ползунки бюджета (`countries.budget_*`, целые
  проценты `u8`, в сумме 100; на старте — `budget_*` из `defines.csv`, у всех стран одни) делят его на пять счетов
  точно (`mint_shares`). Вложения в Army, Production, Government и стабильность только копятся (что они дают — M9);
  доля Treasury уходит в казну.
- **Инфляция** (`countries.inflation`, `float`, в процентах): за месяц с доходом > 0 растёт на `budget_treasury` / 100 ×
  `treasury_inflation` / 12 (EU3 1:100: 60% в Treasury — +0.6 за год). Ниже нуля не опускается (падать ей пока не от
  чего); множитель к расходам придёт с расходами.
- **Команда `budget`** — пять процентов (Army, Production, Government, стабильность, Treasury); не в сумме 100 или нет
  такой страны — отказ с предупреждением («Команды»). В игре — окно «Dev» по F9 (docs/CODE.md, «Отладочное»): казна,
  месячный доход (налог, производство, изумруд), перепись, инфляция, вложения и пять ползунков (сдвиг одного пропорционально
  двигает остальные; доли уходят командой, когда ползунок отпущен).
- Раскладка: раз в месяц по провинциям — один проход, суммы в рабочие столбцы `WorldIncome` (`Budget`, владеет
  `World`), потом по странам.
- В `mapcraft_sim` — сценарии `treasury` и `production` (docs/SIMULATION.md), помесячный ряд `treasury.csv`.

## Содержание армии (`game/economy/upkeep.h`)
Решения пользователя 28.11.2026 — числа EU3, способы EU4 (archeologyEU4 `UtilityAI/research/CAVALRY.md`):
- **Лимит сил** — `force_limit_base` (6, у каждой страны) + `force_limit_per_base_tax` (0.25) × (Σ `base_tax` провинций,
  которыми страна владеет, оккупированных тоже, + `capital_tax` за столицу), округлённое вниз до целых полков (1.8 —
  это 1; решение пользователя), не меньше 0: целое и в правилах, и в военном счёте, и в UI. Полк идёт в лимит
  единицей при любой силе. Его же читает военный счёт («Война»).
- **Содержание за месяц** — база × `maintenance` / 100 × (1 + max(0, `force_limit_extra_cost` × (полков − лимит) /
  лимит)) × (1 + инфляция / 100) (при лимите 0 — × (1 + `force_limit_extra_cost` × полков)); база — Σ по полкам: сила / 1000 × `cost` типа × `land_maintenance` (2.5%): полк
  платит за людей, которые в нём есть (EU4). Сверх лимита — пропорционально (`force_limit_extra_cost` 1, как EU3; в
  EU4 — 2). Списывается из казны 1-го числа после месячного дохода (`ledger::spend`); казна может уйти в минус —
  заглушка до займов и банкротства.
- **Ползунок содержания** (`countries.maintenance`, целые проценты `maintenance_min`..100, на старте
  `maintenance_start`): множит цену и ставит потолок морали полков — `min_maintenance_morale` (0.2) макс. морали страны
  при 50%, линейно до максимума при 100% (`morale_ceiling`; при 100% потолка нет, мораль выше максимума остаётся).
  Хранимая мораль ползунком не меняется: UI (плашка, подсказка) показывает меньшее из морали и потолка, поэтому
  опущенный ползунок виден сразу, а возвращённый до 1-го числа мораль возвращает. Срезается мораль до потолка на
  месячном тике (у всех полков страны, в бою тоже; «Восстановление» потом набирает только до потолка) и когда армия
  вступает в бой. Пополнений при 50% нет — придут с подкреплением.
- **Команда `maintenance`** — процент; вне `maintenance_min`..100 или нет такой страны — отказ. В игре — ползунок
  «Army maintenance» в окне «Dev» (применяется, когда отпущен), там же содержание, полки и лимит.
- Раскладка: раз в месяц — проход по провинциям (лимит) и по полкам (база, число), суммы в рабочие столбцы
  `WorldUpkeep` (`Budget`); `army_upkeep` — то же для одной страны (UI, ряд).
- В `mapcraft_sim` — сценарий `upkeep`, ряды `treasury.csv` (полки, лимит, ползунок, содержание) и `armies.csv`
  (потолок морали).

## Команды (`game/commands.h`)
- **Команда** — обычные данные: вид (`move_army` — идти в провинцию, `declare_war` — объявить войну, `peace` —
  предложить мир, `budget` — поставить ползунки бюджета, `maintenance` — ползунок содержания), страна, которая её отдаёт, армия — `ArmyRef` (слот +
  поколение), провинция, страна-цель (кому объявлена война или предложен мир), доли ползунков, процент содержания и список провинций мира — вид на список, пока команду ставят или исполняют;
  очередь хранит свою копию (столбец списков, у команды — начало и длина).
- **Одна очередь** для игры и `mapcraft_sim` (потом и сети): `World::post` ставит команду на сегодня, место на шкале
  времени — (день, номер), номер считает посты по порядку (в сети его будет выдавать хост). Очередь — столбцы по
  полям команды: простые поля — список `MC_COMMAND_FIELDS` (X-macro: из него раскрываются поля `Command`, столбцы
  очереди, пост, исполнение и сдвиг; новое поле — одна строка), список провинций мира — свой код.
- **Исполняются между днями**, по (день, номер): `World::run_commands` — в начале каждого дня `advance_days` и сразу
  после поста в игре (`Shell`), поэтому приказ в паузе действует мгновенно. Это второй, кроме дня, путь, которым
  меняется `WorldState`, — тоже правила самого `World`. Очередь — не состояние: в игре команды исполняются, как только
  поставлены, `mapcraft_sim` ставит команды дня в его начале, так что между днями очередь пуста.
- **Проверка при исполнении**: армия разрешается по ссылке (погибшей армии или старому поколению приказ не доходит),
  она должна быть страны, отдавшей приказ, а до цели должен быть путь по суше; война — между двумя разными
  существующими странами, которые ещё не воюют и без перемирия, и есть свободный слот; мир — «Война»; бюджет — «Казна»; содержание — «Содержание армии».
  Иначе ничего не меняется, в лог — предупреждение с причиной.

## Движение армий (`game/movement.h`)
Как в EU4 (реверс `CalculateNeighborPaths`, `ProgressMovementOneDay`, `RecalcIsMovementLocked`; EU4
`archeologyEU4/UtilityAI/research/MOVE.md`):
- **Граф переходов** — кэш `Movement`, строится после загрузки из карты и `provinces.terrain`: только суша (пустошь,
  моря и озёра не проходятся; декоративные озёра — суша). Стоимость шага к соседу — длина пути марша в пикселях карты
  (`MapData::march_length`: кривая от точки армии до точки армии только по земле двух провинций, docs/MAPFORMAT.md,
  «Пути марша»; через узкую общую границу она длиннее прямой, и путь через третью провинцию может выйти дешевле —
  Golemtor → Frostheath идёт через Dripstoneshire) × `movement_cost` провинции, **в которую** идёт шаг
  (`terrain.csv`: равнина 1, лес и тайга 1.2, холмы 1.2, пустыня 1.1, болото и горы 1.35, джунгли 1.5 — решение
  пользователя). Туда и обратно поэтому по-разному: в горы дольше, чем с гор. Провинция без terrain — множитель 1.
  У шага ещё флаг реки (`MapData::march_river`: путь марша пересекает реку, docs/MAPFORMAT.md, `MPTR`) — для
  переправы в бою; на марш он не влияет.
- **Скорость** — `kMarchPerDay` = 6.3 единицы стоимости в день, у всех родов войск одна. В EU4 — 2.1 (шаг стоит
  пиксели / 3, армия проходит 0.7 в день), но наши провинции в пикселях крупнее: решение пользователя — втрое быстрее.
  Шаг к соседу — медиана 70 px пути марша (прямая — 67 px), около 11 дней по равнине.
- **Путь** — самый дешёвый по стоимостям шагов, при равенстве — к меньшему id; ищется Дейкстрой от цели назад (по
  стоимостям шагов в обратную сторону), поэтому шаг из любой провинции пути не зависит от того, откуда марш начался
  (армия хранит только цель, не путь).
- **Марш по дням**: армия в своей провинции (`province`), пока прогресс шага (`progress`) не дойдёт до его стоимости;
  каждый день к нему прибавляется скорость. Дошёл — армия в следующей провинции (`next`), остаток прогресса
  переходит на следующий шаг; в цели (`destination`) марш кончается, прогресс — 0.
- **Новый приказ и блокировка** (`kMoveLock` = 0.5, EU4 `MOVE_LOCK_PERCENTAGE`): пока прогресс не больше половины
  стоимости шага, приказ действует из провинции, где армия стоит: тот же первый шаг — прогресс сохраняется, другой —
  шаг начинается с 0; приказ в её же провинцию — **отмена**, армия стоит там. Больше половины — шаг заблокирован:
  приказ (и в её же провинцию) действует с провинции, куда шаг ведёт; армия сначала дойдёт туда.
- **Кэш**: граф и рабочие столбцы поиска (`build`, после загрузки), стоимость текущего шага каждой армии и шаг
  после него (`army_after`: куда марш пойдёт из следующей провинции, 0 — там конец; `rebuild_steps`, после загрузки и
  `restart`). Шаг после ищется на шаг вперёд — когда шаг начинается или меняется цель — и при приходе берётся
  следующим шагом: граф не меняется, поэтому это ровно тот шаг, который нашёл бы поиск в этот день; по нему же
  фигурка идёт сквозь провинцию без остановки. Раскладка (CLAUDE.md, «Раскладка данных»): всё — столбцы `Column` (64 байта,
  длина кратна 16), граф — CSR (`offsets_`, `to_`, `cost_`, `back_`), куча поиска — два столбца (стоимость,
  провинция), прибывшие за день и из них пришедшие через реку — битовые маски `u64`. День марша — явный SSE2 по 8 слотов (`next` → маска, `progress`
  += скорость, сравнение со стоимостью шага, `movemask` в слово маски), без ветвлений; ветвится только разбор
  прибывших по маске, в порядке слотов. Поиск пути — по графу, разрозненный по природе; зовётся только при приказе и
  приходе. Рабочие столбцы марша и поиска задаются при загрузке и переиспользуются.

## Время
Единица времени — день. Всё это код, не данные: календарь и старт в `data/` не лежат.
- **Календарь** (`game/calendar.h`) — заглушка до спецификации сеттинга: 12 месяцев (January … December) по 30 дней,
  год — 360. Дата — число дней от 1 January, year 1; `Date` {год, месяц, день} получается из него без хранения. Старт
  — 1 January 1; формат `17 August 201`. Дней недели нет.
- **Дата** — одно число, поэтому лежит в `World` (`day()`, `date()`), а не среди столбцов `WorldState`. Меняет её только
  `World::advance_days(n)` — единственный путь продвижения мира (`n` дней подряд, внутри — закрытый `tick_day`, правила
  одного дня); `World::restart()` возвращает старт.
- **Темп** (`view/pace.h`) — реальное время, поэтому вне симуляции (`mc_sim`), мира не знает: скорость 1–5 и пауза;
  решает только, сколько дней пройдёт. Скорости 1–4 — месяц за 60, 30, 15 и 5 секунд (набежавшие дни — одним вызовом);
  скорость 5 — как позволяет CPU: по дню, пока не истёк бюджет кадра (`Pace::kFrameBudget`, 8 мс), но минимум один. Кадр длиннее `Pace::kMaxFrame` (0.25 с) на скоростях 1–4 считается таким, чтобы не сыпать днями после
  затыка. Новая партия начинается на паузе, скорость 3.
- **Кто кого зовёт.** `Shell::frame` → `Pace::advance(dt, run)` → `World::advance_days(n)`. `Pace` хранится в `Shell`;
  вне фазы `playing` (`Session::playing()`) время стоит и кнопки темпа ничего не делают. Дни идут до отрисовки карты
  и UI в том же кадре. `mapcraft_sim` зовёт ту же `World::advance_days`.
- **Тик.** День `advance_days`: сначала команды дня (`run_commands`), потом `tick_day` — марш армий, бой, осады и
  `++day_`.
  Если новый день — 1-е число месяца, сразу за ним `tick_month` (на старте игры его нет). **Месячный тик — основной**
  для правил не о марше и бое (решение пользователя 28.11.2026). Порядок записан в одном месте, `World::tick_month`:
  1 January сначала годовой тик `tick_year` (перепись, «Казна»), потом восстановление армий («Восстановление»), рост
  гарнизонов («Осада и оккупация»), конец перемирий и месячный доход по ползункам («Казна»); дальше придут
  производство, содержание, пополнение людей (M8).
  Правила дня пока дешёвые, поэтому скорость 5 за кадр делает очень много дней. Счётчик дней — `u32` (около 12 млн
  лет).
