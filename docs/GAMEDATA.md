# Игровые данные (`data/`)

Содержимое игры — CSV-файлы, а не C++. Движок знает только схему; файлы задают, что именно существует.
`mapcraft_editor` пишет те же файлы, которые читает игра. Геометрия карты живёт отдельно, в `build/map/world.mcmap`.
«Истории» как в EU4 нет: одна дата старта (зашита в `game/calendar.h`, не в `data/`).

Игровых данных в `data/` пока нет — только заголовки CSV (заполнена лишь таблица биомов карты `common/biomes.csv`):
содержимое мира Майнкрафта задаёт пользователь. Схема ниже унаследована от
Tamriel Universalis (поля EU4); под Vic2 её переделывает M2 (docs/ROADMAP.md, docs/ECONOMY.md).

## Файлы
- Формат: CSV UTF-8, первая строка — заголовок.
- Ссылки между файлами — только по строковым ключам: латиница, `snake_case`; у стран — тег из трёх символов
  (заглавные латинские буквы или цифры).
- Номера стран и записей списков существуют только в памяти: их раздаёт загрузчик по порядку строк. Провинции —
  исключение: их номер — `id` карты.
- Цвет записывается как `#RRGGBB` и обязателен; в остальных колонках пустая ячейка значит «не задано».

| Файл | Колонки | Что |
|---|---|---|
| `common/terrain.csv` | key, name, color | логический terrain провинций (не вид карты); ставится руками в редакторе |
| `common/biomes.csv` | key, name, color, density, minecraft_biome, top, side, under, deep, shore, snow_top, snow_side, snow_line, trees, tree_density, tree_line, village | биомы вида карты (см. ниже); не игровые данные, редактор его не правит |
| `common/countries.csv` | tag, name, adjective, color | определения стран; `adjective` — для частей, отрезанных от столицы, по умолчанию = name |
| `common/goods.csv` | key, name, price, icon | товары; `price` — стартовая цена в изумрудах за единицу на каждом рынке, > 0 (у изумруда всегда 1); `icon` — предмет Майнкрафта для UI (M6), пока не читается |
| `common/pop_types.csv` | key, name, essential, everyday, luxury, cash, look, skin | типы попов: потребность каждого уровня на человека в день (пусто = 0); `cash` — стартовые деньги на человека, в изумрудах; `look`, `skin` — профессия и биом жителя для UI (M6), пока не читаются |
| `common/needs.csv` | tier, good, weight | чем закрывается уровень потребностей (`essential`, `everyday`, `luxury`): товары уровня взаимозаменяемы, `weight` — сколько уровня закрывает единица товара |
| `common/rgo_types.csv` | key, name, color, workers, owners, wages, outputs, icon | типы RGO: `workers` — кто работает, `owners` — чьему попу в провинции идёт доход (оба — типы попов); `wages` — доля дохода работникам, 0..1, остальное владельцам; `outputs` — выход на работника в день через пробел (`meat:1 leather:0.3`); `icon` — для UI (M6; `entity:cow` — 3D-рендер моба), пока не читается |
| `setup/provinces.csv` | id, name, owner, controller, cores, terrain, rgo | провинции суши на старте |
| `common/defines.csv` | key, value | числа экономики: `price_step` (на сколько цена меняется за день, доля себя), `price_epsilon` (перекос, меньше которого цена стоит), `price_floor` (пол, доля стартовой цены); шаг и ε — от 0 до меньше 1, пол — больше 0 и до 1 (цена никогда не доходит до 0); каждый ключ один раз; без файла — 0.01, 0.05, 0.1 |
| `common/markets.csv` | key, name, color | рынки; рынок — из целых регионов (docs/ECONOMY.md); необязателен |
| `setup/regions.csv` | region, name, market | регион карты (номер из `regions.csv` карты) → рынок; пусто — без рынка |
| `setup/pops.csv` | province, name, pop_type, size | попы на старте: одна строка на провинцию и тип; нет строки — нет попа |
| `setup/countries.csv` | tag, capital | страны на старте: столица (id провинции) |

Подробности `common/biomes.csv` (читают инструменты карты и игра при запуске, docs/RENDER.md «Облик блоков»):
- `color` — цвет биома в `biome.png`; `density` — плотность провинций при генерации карты (1 — обычная, меньше —
  провинции крупнее);
- `minecraft_biome` — ванильный биом (`data/minecraft/worldgen/biome/<имя>.json` в jar), чьи температура, осадки и
  цвета дают оттенок травы и воды;
- блоки — имена текстур `assets/minecraft/textures/block/<имя>.png` из jar: `top` — верх, `side` — бок верхнего блока,
  `under` — бок следующих трёх, `deep` — глубже, `shore` — верх и бок берега (суша на блок выше моря или озера);
- `snow_line` — высота ступени (0–16, как `height` в корневом `provinces.csv` карты), с которой верх — `snow_top`, бок верхнего блока —
  `snow_side`; пусто — снега нет, тогда `snow_top` и `snow_side` можно не заполнять;
- `trees` — деревья: имена configured feature из jar (`data/minecraft/worldgen/configured_feature/<имя>.json`)
  через пробел, повтор — больший вес; поддержаны деревья с прямым и раздвоенным стволом (листва blob, spruce,
  acacia), столбики блоков (кактус) и одиночные блоки (сухой куст); `tree_density` — доля блоков карты с деревом (0–1, не
  больше дерева на блок); `tree_line` — ступень, с которой деревья не растут (пусто — растут везде);
- `village` — стиль домиков-городов (деревни Майнкрафта): `plains`, `desert`, `savanna`, `taiga`, `snowy`; выше
  `snow_line` биома — всегда `snowy`;
- биом, который есть в `world.mcmap`, обязан быть в таблице (ключ — `key`); правка блоков и оттенков видна после
  перезапуска, без пересборки карты; новый биом или новый `color` — правка `biome.png` и `bake.py`.

Флаги стран — `<TAG>.png` в папке `assets/flags` (путь задаётся при сборке, `MC_DEFAULT_FLAGS`; в репозитории папки
нет, картинки в git не идут). Файл необязателен: без него флаг — квадрат цвета страны. Решение пользователя на будущее —
флаги-баннеры с узорами (данные, не арт; CLAUDE.md, «Вид»).

Подробности `setup/provinces.csv`:
- `id` — номер провинции карты;
- `name` нужен только человеку и для diff, загрузчик его не читает;
- `cores` — теги через пробел;
- `rgo` — тип RGO, ключ из `common/rgo_types.csv` или пусто. Тип и terrain ставит пользователь руками: код не
  ограничивает и не подсказывает, что где может быть.

Справочники M2 (что в них лежит и почему) — docs/ECONOMY.md, «Набор M2». Все необязательны: без них игра грузится
без экономики.

Столица страны — `capital` в `setup/countries.csv`; без неё (или если провинция не своя) столицей считается первая
провинция страны, наименьший id (`seat`, `game/countries.h`).

Провинция без владельца допустима. Морских строк пока нет.

Номера провинций в `data/setup` — это id карты. **Ссылка на провинцию** в `data/setup` — колонка `id` в
`provinces.csv`, `capital` в `countries.csv`, а в любом другом файле — колонка `province` (так и называть её в новых
файлах). Ссылка на регион — колонка `region`, номер региона карты (1-based, `PREG`): номера регионов при правке
провинций не меняются. Перенумерация карты (`edit_provinces.py sync-lakes`, когда удаляется озеро) переписывает именно эти колонки
на новые id (`SETUP_COLUMNS` в скрипте), строки `provinces.csv` — в новом порядке. Строка удалённой провинции в
`provinces.csv` выбрасывается; любая другая ссылка на неё останавливает правку до записи файлов.

**Проверка при загрузке.** Неизвестный ключ или тег, повтор, id не суши или плохое число — это ошибка с файлом и
строкой, а не тихий ноль. Предупреждения (лог, `mapcraft_editor --check` и панель «Countries» редактора) — то, через что
проходит правка:
- столица вне владений своей страны;
- **товар-сирота**: его не делает ни один RGO или не берёт ни одна потребность (изумруд — деньги, ему потребитель не
  нужен);
- уровень потребностей, который какому-то типу попа нужен, но который не закрывает ни один товар;
- когда рынки есть: регион без рынка и рынок без регионов. Проверить данные без окна:
`mapcraft_editor --check`.

## В памяти (`code/src/game/game_data.h`)
- **Содержимое и состояние — разные типы.**
  - `Content` — справочники и `CountryDefinitions` (тег упакован в `u32`, имя, прилагательное, цвет). Все строки
    живут только здесь; после загрузки не меняется.
  - `WorldState` — только столбцы: `Provinces`, `Pops` и `CountryStates` (столица) с тем же индексом, что у
    стран. Симуляция меняет только его.
- **Метки** (`game/game_data.h`, у каждой структуры): **сохраняется** — `WorldState` и его части, то, что меняют дни
  и что попадёт в сейв; **контент** — `Content` и его части, неизменны после загрузки `data/common` и карты; **кэш** —
  `EconomyCache`, после загрузки и `restart` строится из двух первых (`prepare_economy`), не сохраняется. Размеры
  (`count`, `stride`, `types`, `goods`) — ни то, ни другое: следуют из контента и карты. Дата (`World::day`) тоже
  сохраняется, но лежит в `World`.
- **Список сохраняемого** — `game/saved_state.h`, `for_each_saved`: каждый столбец и число `WorldState` под
  стабильным именем (`pops.size`, `money.cash`…), в одном порядке, столбцы целиком с дополнением. По нему идут дамп и
  контрольная сумма `mapcraft_sim`, позже — сейв. `static_assert` на `sizeof(WorldState)` ловит новое поле, которое
  забыли разметить и внести в список.
- **Индексы.** Провинция и страна — `u16`, 0 = нет; провинции 1..N, как в карте. Terrain, тип RGO, тип попа
  и товар — `u8`, 0 = нет, поэтому в каждом списке не больше 255 записей (проверяется).
- **Попы** (`Pops`) — матрица тип × провинция: строка на тип попа, в строке столбец провинций; размер типа `t` в
  провинции `p` — `size[t * stride + p]`, `stride` = число провинций, дополненное до кратной 16 (каждая строка
  выровнена на 64 байта). Место (`t`, `p`) — id попа, стабильный; размер 0 — попа нет. Строка 0 («нет») пустая.
- **Раскладка.** Каждое поле — свой столбец длиной N+1, дополненной до кратной 16, с выравниванием 64 байта
  (`Column<T>`, `AlignedAllocator`). Цикл по провинциям идёт по столбцу подряд.
- **Числа — `float`**; балансы и требования (когда появятся) — `i64` (docs/ECONOMY.md, «Деньги в i64»). Симуляция
  строго детерминирована (мультиплеер будет): правила — docs/SIMULATION.md, «Детерминизм».
- **Коры** — битовая матрица провинция × страна (по `u64`-слову на 64 страны).
- **Владение:**
  - в игре `GameData` принадлежит `game/World`, наружу он отдаёт только `const`;
  - карта (`App::set_game`) и UI только читают;
  - редактор держит свой `GameData` и правит только `state`; undo хранит снимки `WorldState`.

## Деньги (`core/money.h`, `game/economy/`)
- **Тип.** `Money` — `i64`, целые крупинки, 10⁶ на изумруд. Сумма считается во `float`/`double`, округляется до
  крупинок один раз (`to_grains`), и ровно это целое переходит со счёта на счёт. `to_emeralds` — только для показа.
- **Счета** — `Balances` в `WorldState`: один столбец `cash`; счёт попа — его место в `Pops` (`t * stride + p`).
  Казна, здания и пул получат свои диапазоны того же столбца.
- **Пишет только `ledger`:** `start` (старт: размер попа × `cash` его типа), `mint` (из ничего — только шахта),
  `transfer` (точная сумма между счетами; не уходит в минус). Счётчики `flows` — сколько прошло по каждому виду
  (`Flow`: `mine`, `wages`, `sales`). `settle` — пакетный расчёт: каждый плательщик платит ровно своё, сумма делится
  между получателями по весу (каждому — целая часть доли), остаток деления — получателю с наибольшим весом (первому из
  равных), ни одна крупинка не теряется.

## Экономика дня (`game/economy/economy.cpp`)
Порядок фаз записан только в `economy_day`. Кроме состояния день берёт `EconomyCache` (держит `World`, не сохраняется,
`prepare_economy` строит его при загрузке и `restart`): рынки плоскими списками — провинции и попы рынок за рынком, по
id (`province_first`, `pop_first`); товары каждого уровня от дешёвых за единицу уровня; рабочие столбцы расчёта (спрос,
покупка, оплата попов, получатели и веса), которые переиспользуются — в тике память не выделяется. Меняются рынки
регионов — `prepare_economy` заново.
1. **Добыча.** RGO, у которого среди выходов изумруд, чеканит `работники × выход` владельцам (`owners`), и они
   переводят работникам их долю (`wages`).
2. **Производство.** Каждый RGO добавляет `работники × выход` каждого своего товара (кроме изумруда) в свой запас:
   `Stock` в `WorldState` — матрица товар × провинция (`g * stride + p`). Товар остаётся запасом своего RGO, пока не
   продан; не портится.
3. **Рынки.** Провинция в рынке своего региона (`Content::province_region` из карты → `setup/regions.csv`); на каждом
   рынке уровни потребностей по порядку Essential → Everyday → Luxury:
   - спрос уровня — сумма `потребность × размер` его попов рынка; предложение — запасы товаров уровня во всех
     провинциях рынка;
   - рынок закрывает спрос товарами уровня, **самыми дешёвыми за единицу уровня** первыми (цена рынка / `weight`,
     при равенстве — по номеру товара); не хватает — каждый поп получает одну долю `min(1, S/D)`;
   - поп без денег берёт то, на что хватает его денег; платит по средней цене купленного;
   - каждый RGO рынка продаёт одну и ту же долю своего запаса товара; деньги (`settle`, `Flow::sales`) идут его
     работникам и владельцам по `wages`;
   - `Pops::filled` — сколько уровня поп получил за день (0..1), по столбцу на уровень; это показывает тултип;
   - в спрос дня для цен (`EconomyCache::market_demand`) идёт то, что попы хотели купить **на свои деньги** по самой
     дешёвой цене на рынке; что не досталось — делится между товарами, которые кончились, по тому, сколько уровня
     каждый из них давал. Никто не может заплатить — ничего не продаётся, запасы остаются.
   Потребляют только попы; запасы, которые никто не купил, копятся.
4. **Цены** (`MarketPrices` в `WorldState` — матрица товар × рынок, `g * stride + m`; старт — `goods.csv`). Предложение
   S — **весь запас** рынка до торговли (`market_supply`; решение пользователя 24.11.2026: не выпуск дня), спрос D —
   из шага 3. Запасы не портятся, поэтому товар с постоянным излишком уходит к полу и стоит там, пока производство не
   научится отвечать на цену (M5). Перекос `(D − S) / max(D, S)`; если он больше
   `price_epsilon`, цена × `(1 + price_step × перекос)`, но не ниже `price_floor` от стартовой. Товара на рынке нет
   совсем (S = 0) — цена там стоит (иначе росла бы без конца). Изумруд всегда 1. Один плотный проход по строке товара.
- **Инвариант мира** — `ledger::balanced`: сумма `cash` = старт + всё добытое. `World` проверяет его после каждого дня и
  при первом нарушении пишет ошибку в лог. `World::restart` возвращает состояние, каким оно загрузилось.
- **Редактор** правит старт: после каждой правки попов стартовые деньги пересчитываются; в `data/` деньги не пишутся
  (они следуют из попов и `cash`).

## Время
Единица времени — день. Всё это код, не данные: календарь и старт в `data/` не лежат.
- **Календарь** (`game/calendar.h`) — заглушка до спецификации сеттинга: 12 месяцев (January … December) по 30 дней,
  год — 360. Дата — число дней от 1 January, year 1; `Date` {год, месяц, день} получается из него без хранения. Старт
  — 1 January 1; формат `17 August 201`. Дней недели нет.
- **Дата** — одно число, поэтому лежит в `World` (`day()`, `date()`), а не среди столбцов `WorldState`. Меняет её только
  `World::advance_days(n)` — единственный путь продвижения мира (`n` дней подряд, внутри — закрытый `tick_day`, правила
  одного дня); `World::restart()` возвращает старт.
- **Темп** (`view/pace.h`) — реальное время, поэтому вне симуляции (`mc_sim`), мира не знает: скорость 1–5 и пауза;
  решает только, сколько дней пройдёт. Скорости 1–4 — месяц за 60, 30, 15 и 7 секунд (набежавшие дни — одним вызовом);
  скорость 5 — как позволяет CPU: по дню, пока не истёк бюджет кадра (`Pace::kFrameBudget`, 8 мс), но минимум один. Кадр длиннее `Pace::kMaxFrame` (0.25 с) на скоростях 1–4 считается таким, чтобы не сыпать днями после
  затыка. Новая партия начинается на паузе, скорость 3.
- **Кто кого зовёт.** `Shell::frame` → `Pace::advance(dt, run)` → `World::advance_days(n)`. `Pace` хранится в `Shell`;
  вне фазы `playing` (`Session::playing()`) время стоит и кнопки темпа ничего не делают. Дни идут до отрисовки карты
  и UI в том же кадре. `mapcraft_sim` зовёт ту же `World::advance_days`.
- **Ограничение.** Пока тик — это `++day_`, скорость 5 за кадр делает сотни тысяч дней: бюджет уходит на пустой цикл.
  Настоящая цена дня появится вместе с симуляцией. Счётчик дней — `u32` (около 12 млн лет).
