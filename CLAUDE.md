# MapCraft — правила для агента

Фанатская некоммерческая глобальная стратегия в сеттинге Майнкрафта: EU4 + POPs и экономика Victoria 2, воксельная
карта, UI и звуки Майнкрафта. Отдельная игра `mapcraft.exe` и редактор провинций `mapcraft_editor.exe`. Сначала прочитай
`README.md` и `docs/HANDOFF.md`, потом нужный `docs/*.md`. С пользователем говори по-русски. Весь код пишет агент.

## Как работать
- **Никакого кода без понимания связей.** Перед новым слоем или фичей определи модули, владельцев данных, время жизни
  объектов и направление зависимостей. Код — только после этого.
- **Модульность.** Один класс или модуль — одна ответственность. Никогда не сваливать в один класс UI, правила игры и
  ввод. Новая подсистема — свой модуль в своём слое (см. «Архитектура»).
- **DOD, SoA, SIMD-friendly.** Состояние симуляции хранится столбцами:
  - индексы: `u16` для провинций и стран, `u8` для списков; для POPs — свой индекс (размер решается вместе со
    спецификацией POPs);
  - числа — `float`;
  - столбцы выровнены на 64 байта, длина дополнена до кратной 16;
  - в горячих данных нет строк и указателей;
  - циклы идут по столбцам.

  Мультиплеера и реплеев не будет никогда, поэтому детерминизм не нужен: `float` и параллелизм свободно.
- **Делай только запрошенный шаг.** Спецификации новых фич даёт пользователь. Сам фичи не планируй и не начинай.
- **Никаких отладочных флагов и инструментов в exe** (единственный флаг — `mapcraft_editor --check`).
- **Никаких тестов и проверочных программ — вообще.** Не писать `check.cpp` и ничего подобного на десятки или сотни
  строк, ни в проекте, ни во временной папке. Проверка — сборка `code/build.cmd` без предупреждений. Работу в игре и
  вид проверяет пользователь сам в `mapcraft.exe`; в отчёте прямо пиши, что собрано и чего ты не запускал и не видел.
- **Вся память проекта — только в папке проекта:** `CLAUDE.md`, `README.md`, `docs/`. Не вести память на диске C
  (`~/.claude/.../memory` и любые другие места вне проекта) и ничего туда не писать. Новое правило, решение или
  особенность — в документацию проекта.
- **Без костылей.** Чини причину, а не обходи её. Правь исходник (PNG и CSV карты, `data/`), а не сгенерированный
  вывод.
- **Документация описывает текущее состояние**, инварианты и особенности, а не летопись. Если меняешь систему, правь
  её документ в том же шаге. `docs/HANDOFF.md` — исключение: он про происхождение проекта и открытые вопросы, его
  чистят по мере их закрытия.
- **Git:** репозиторий новый, без истории TU; remote пока не задан, ветка `main`. Коммит и пуш — только по просьбе.
  Бинарники (png, ttf, npz, ogg, jar…) в репозиторий не идут.
- **Игровые данные** — CSV в `data/`; заполняет их пользователь в `mapcraft_editor`.
- Не проси computer-use доступ к окну редактора или игры. Не сканируй диски целиком — пути известны.

## Архитектура (`code/src`)
| Слой | Что | Не знает |
|---|---|---|
| `core/` | ввод, камера, карта (`world.mcmap`), CSV, раскладка названий EU4 | платформу, игру |
| `render/` | D3D11, вся карта | игру, UI |
| `game/` | `GameData` = `Content` (неизменяемые справочники, все строки) + `WorldState` (только SoA-столбцы); `World`; `Session` | UI, D3D |
| `ui/` | экраны Dear ImGui; читают состояние, возвращают `UiCommands` | как меняется состояние |
| `app/` | `App` — карта; `bindings.cpp` — все коды клавиш; `Shell` — тонкая склейка для хоста | — |
| `host/win32` | `mapcraft.exe`: окно, swap chain, ввод; всё о платформе — только здесь | — |
| `editor/` | инструмент: `App` + свой `GameData` + панели | — |

Инварианты:
- `World` владеет `GameData` и отдаёт наружу только `const`. `WorldState` меняют только правила самого `World`.
- Время: дата — скаляр в `World`, не в `WorldState`. `World::tick_day()` зовёт только `Session::advance` из
  `Shell::frame` (до карты и UI), темп задаёт `Pace`. Скорость 5 ограничена бюджетом кадра, потолка дней нет
  (docs/GAMEDATA.md, «Время»).
- `App` читает данные игры через `const GameData*` и не знает клавиш; камера получает `CameraInput`.
- В `Shell` объект `world_` объявлен раньше `app_`: `App` держит указатель на данные мира.
- Порядок кадра: карта → UI. Курсор — системный (игра свой не рисует).
- Перелёт камеры стартует только после `App::ensure_camera`: отложенный сброс камеры отменил бы перелёт.
- `Editor` смешивает UI и логику правки. Для инструмента это допустимо, но в игру такой шаблон не переносить.

## Намеренные особенности — не «чинить»
- **Названия на карте.** `core/labels.cpp` — перенос алгоритма названий EU4 один в один; в TU сверен с LabelPython:
  89/89, расхождение до 1e-4 px. Странности оригинала намеренные.
  - Единственное отличие: `kMinBridgedPiece` = 1 вместо 2, чтобы островки подписывались вместе с материком.
  - Группировка одна для всех режимов: регионы, культуры и религии — «страны» без столиц.
- **Названия вод** ниже по иерархии, чем названия суши: никогда не лежат на суше или на других надписях; вода, где
  название не влезает, остаётся без него.
- **Провинции после генерации заморожены.** Правки — только через `tools/mapgen/edit_provinces.py`, не
  перегенерировать. Единственный источник истины для берегов — `land.png`.
- **Имена провинций** живут в двух местах: корневой `provinces.csv` (из него запекаются надписи) и колонка `name` в
  `data/setup/provinces.csv` (только для человека). Переименовывать по id в обоих.
- **Сборка карты.** `tools/labels/provinces.py` идёт до `positions.py`: города обходят буквы.
- **Порт** есть у каждой сухопутной провинции, граничащей с морской. Озёра не считаются. Декоративные озёра — суша в
  игре.
- **Камера** умеет высоту рельефа (`Camera::set_ground`), но сейчас её никто не задаёт: карта — плоскость y = 0.
  Воксельная поверхность подключится через этот же хук.

## Вид (решения пользователя)
- **Рендер** следует реверсу EU4: слои встречаются в пиксельном шейдере, режим карты — это только таблица цветов.
- **Карта воксельная** (блоки), не гладкий рельеф. Деревья — настоящие майнкрафтовские (дуб, берёза, ель, джунгли…)
  как декор на карте. Формат исходников для вокселей задаёт пользователь, когда дойдёт до этой работы.
- **UI — Майнкрафта**, делается кодом: свой небольшой UI-слой (спрайты, nine-slice по `.mcmeta`, растровый шрифт
  `font/default.json`, целочисленный GUI scale, точечная выборка) вместо стилизации ImGui. Спрайты, шрифт и звуки
  берутся из установленного у игрока Майнкрафта во время работы игры; то, чего в Майнкрафте нет, собирается из тех же
  примитивов. Композицию окон пользователь проверяет по скриншотам.
- **Границы** стран — как EU4 `border5`, поверх границ провинций.
- **Цвета надписей:** чернила RGB 32,30,26, ореол 180.

## Ассеты Майнкрафта
- Проект фанатский и некоммерческий. Ассеты Mojang (текстуры, звуки, шрифт, модели) **не распространяются**: не
  класть их в репозиторий, не копировать в `assets/`, не запекать в файлы, которые можно раздать. Игра читает их из
  `.minecraft` игрока (jar версии и индекс ассетов).
- Ассеты Paradox (EU4, Victoria 2) — только для изучения, не копировать.

## Окружение
- **Сборка:** `code/build.cmd` → `code/build/release/`.
  - Нужны MSVC Build Tools (`D:\Dev\BuildTools`) и переменная `VCPKG_ROOT` (`D:\Dev\vcpkg`), триплет
    x64-windows-static.
  - Если открыт `mapcraft.exe` или редактор, линковка падает (LNK1168). Переименуй запущенный exe, процесс
    пользователя не убивай.
- **Python 3.14** + numpy/scipy/scikit-image/Pillow/numba/fontTools.
  - `tools/labels` нужен `D:\Dev\Projects\eu4\archeologyEU4\Labels\LabelPython`.
  - Правя файлы срезами между якорями, проверяй, что якорь уникален, а срез не пустой.
- **EU4** (`C:\Games\EUIV`) и `D:\Dev\Projects\eu4\archeologyEU4\` (реверс eu4.exe с pdb: `Render`, `Labels`,
  `UtilityAI`) — только для изучения.
- Старый проект Tamriel Universalis лежит в `D:\Dev\Projects\MinecraftUniversalis` — только как справка (там гладкий
  рельеф, Blender-модели, хост SKSE). Код оттуда не переносить без решения пользователя.

## Известные долги
- `edit_provinces.py` при перенумерации не переписывает `data/setup/provinces.csv`, и данные съедут на чужие
  провинции. Исправить до первой правки карты с заполненными данными.
- `mapcraft.exe` и `mapcraft_editor.exe` дублируют Win32-код окна и ввода.
