# MapCraft — правила для агента

Фанатская некоммерческая глобальная стратегия в сеттинге Майнкрафта: EU4 + POPs и экономика Victoria 2, воксельная
карта, UI и звуки Майнкрафта. Отдельная игра `mapcraft.exe` и редактор провинций `mapcraft_editor.exe`. Сначала прочитай
`README.md` и `NEXT.md`, потом нужный `docs/*.md`. План — `docs/ROADMAP.md`. С пользователем говори по-русски.
Весь код пишет агент.
Всё, что видит игрок (интерфейс, названия на карте, тексты игры, данные в `data/`), — только на английском;
документация и разработка — на любом удобном языке.

## Как работать
- **Никакого кода без понимания связей.** Перед новым слоем или фичей определи модули, владельцев данных, время жизни
  объектов и направление зависимостей. Код — только после этого.
- **Модульность.** Один класс или модуль — одна ответственность. Никогда не сваливать в один класс UI, правила игры и
  ввод. Новая подсистема — свой модуль в своём слое (см. «Архитектура»).
- **DOD, SoA, SIMD-friendly.** Состояние симуляции хранится столбцами:
  - индексы: `u16` для провинций и стран, `u8` для списков; для POPs — свой индекс (размер решается вместе со
    спецификацией POPs);
  - числа — `float` с правилами детерминизма (ниже); исключение — **балансы и требования: `i64`**, фиксированная
    точка, масштаб — 10⁶ крупинок на изумруд (по умолчанию; открытый вопрос в `docs/ROADMAP.md`). Балансы — всё, что
    лежит на счету и переходит из рук в руки (docs/ECONOMY.md, «Деньги в i64»);
  - столбцы выровнены на 64 байта, длина дополнена до кратной 16;
  - в горячих данных нет строк и указателей;
  - циклы идут по столбцам.
- **Симуляция строго детерминирована** (решение 21.11.2026: мультиплеер будет, lockstep): одинаковые команды →
  бит в бит одинаковое состояние на всех машинах, при любом числе потоков. Правила — для кода симуляции, библиотеки
  `mc_sim`: `game/` и `core/` (CSV, данные карты и игры, `det_math`, будущий `money`). Камера, ввод, названия и темп
  живут в модуле вида `view/`, на них правила не распространяются (подробно — docs/SIMULATION.md, «Детерминизм»):
  1. `/fp:precise`, никакого `/fp:fast`, без сжатия в FMA; один набор инструкций, без выбора AVX2/SSE во время работы.
  2. Без функций CRT `exp`, `pow`, `log`, `sin`: только свои реализации (`core/det_math.h`).
  3. Случайность — только из счётного генератора состояния игры `random(seed, день, сущность, назначение)`; никаких
     `rand()`, `random_device`, времени. Косметика и UI берут случайность из другого генератора.
  4. Только дни: `dt`, частота кадров и часы в симуляцию не попадают.
  5. Порядок обхода фиксирован: **`unordered_map` в `mc_sim` запрещён целиком** (поиск по ключу — массивы по id или
     отсортированные векторы; в `app/`, `minecraft/`, `render/` он разрешён — таблицы ассетов); никаких сортировок по
     адресам; сортировка — с полным порядком (при равенстве — по id).
  6. Параллельность только детерминированная: фиксированное разбиение по индексам, суммы в фиксированном порядке,
     никаких атомарных накоплений `float`.
  7. Разбор данных не зависит от локали: `std::from_chars`, не `atof` или `stod`.
  8. Состояние UI (выделение, камера, открытые окна) отдельно от состояния мира.
  9. Сохранение бит в бит; кэши после загрузки пересчитываются детерминированно.
  10. Бот работает только на хосте и выдаёт обычные команды; его случайность — только из генератора мира,
      параллельные решения сортируются по (страна, команда) перед применением.
  11. Контрольная сумма состояния — только в `mapcraft_sim` (режим проверки детерминизма; сам `mapcraft_sim` — M4,
      его ещё нет); debug-сборки нет и не будет. В мультиплеере позже — всегда включена как часть протокола (это не отладочный флаг).
  12. Нет `std::*_distribution`; MXCSR выставляется явно в потоке симуляции.

  Линтер `tools/lint/sim_lint.py` — первый шаг каждой сборки: проверяет `core/` и `game/` на запрещённое и роняет
  сборку. Свои функции математики в `det_math.h` называются `det_<имя>`, чтобы не попасть под запрет имён CRT.
- **Размер файлов.** Файл делится, когда у него больше одной зоны ответственности, то есть его нельзя описать одним
  предложением. Больше ~1000 строк — повод проверить, но не причина делить.
- **Делай только запрошенный шаг.** Спецификации новых фич даёт пользователь. Сам фичи не планируй и не начинай.
- **Ход работ.** План — срезы `docs/ROADMAP.md`. `NEXT.md` — три ближайших шага; ведёт его агент, только из срезов
  роадмапа: чего в роадмапе нет — только от пользователя, новые идеи — строкой в `IDEAS.md`. Если в роадмапе
  следующих шагов нет — прямо сказать «роадмап исчерпан». Начало сессии — прочитать `NEXT.md`, конец — обновить его.
  Результат проверяет пользователь сам; коммит и пуш — только по его просьбе.
- **Отладочное в exe — разрешено, в рамке** (решение пользователя: в TU половину кода съели флаги и их разбор):
  - все переключатели — поля одной структуры `DevOptions` (`app/dev_options.h`); меняются только в окне «Dev» по
    F9, окно строится по структуре. Флагов командной строки нет (кроме `mapcraft_editor --check`), разбора
    аргументов под отладку не писать; сохранение между запусками, если понадобится, — один файл целиком;
  - отладочное только показывает: оверлеи, окна, графики, режимы рендера. Правила игры от переключателей не
    ветвятся, в `mc_sim` их нет. Действия отладки — обычные команды, как у игрока;
  - не больше ~15 переключателей; каждый — строкой в таблице README «Отладочное» (имя, зачем, до когда); в конце
    среза просроченные удаляются. Экономику и ботов сначала смотреть в `mapcraft_sim`, в игре — то, что нужно
    видеть вживую на карте.
- **Тесты — только там, где глазами не проверить:** инварианты денег, детерминизм, сценарии headless-симулятора
  `mapcraft_sim.exe` (docs/SIMULATION.md), линтер запрещённого в исходниках `mc_sim`. Рендер, UI, домики, деревья —
  без тестов, их проверяет пользователь глазами. Против тестов ради тестов:
  - тест проверяет свойство, которое важно для игры («денег = старт + добыто», «два прогона бит в бит»), а не детали
    реализации;
  - тест никогда не подгоняется под код, чтобы стать зелёным. Упал — чинится код, или прямо пиши пользователю, что не
    так. Ослабить проверку — только с согласия пользователя;
  - зелёный тест не означает «работает»: в отчёте всё равно пиши, что не проверено.

  Разовых проверочных программ (`check.cpp` и подобного) не писать, ни в проекте, ни во временной папке. Проверка —
  сборка `code/build.cmd` без предупреждений. Работу в игре и вид проверяет пользователь сам в `mapcraft.exe`; в
  отчёте прямо пиши, что собрано и чего ты не запускал и не видел.
- **Вся память проекта — только в папке проекта:** `CLAUDE.md`, `README.md`, `docs/`, `NEXT.md`, `IDEAS.md`. Не
  вести память на диске C (`~/.claude/.../memory` и любые другие места вне проекта) и ничего туда не писать. Новое
  правило, решение или особенность — в документацию проекта.
- **Без костылей.** Чини причину, а не обходи её. Правь исходник (PNG и CSV карты, `data/`), а не сгенерированный
  вывод.
- **Документация описывает текущее состояние**, инварианты и особенности, а не летопись. Если меняешь систему, правь
  её документ в том же шаге. Исключение — планы и решения, ещё не воплощённые: `docs/ROADMAP.md`, `NEXT.md`,
  `IDEAS.md`, `docs/ECONOMY.md`, `docs/SIMULATION.md`; сделанное и закрытое оттуда убирается или переносится в
  документ системы.
- **Git:** `origin` = github.com/neonbones52/MapCraft, ветка `main`; истории TU в нём нет. Коммит и пуш — только по
  просьбе.
  Бинарники (png, ttf, npz, ogg, jar…) в репозиторий не идут.
- **Игровые данные** — CSV в `data/`; заполняет их пользователь в `mapcraft_editor`.
- Не проси computer-use доступ к окну редактора или игры. Не сканируй диски целиком — пути известны.

## Архитектура (`code/src`)
| Слой | Что | Не знает |
|---|---|---|
| `core/` | (`mc_sim`) карта (`world.mcmap`), CSV, лог, `det_math.h` — математика и MXCSR симуляции | вид, платформу, игру |
| `view/` | ввод, камера, раскладка названий EU4, темп времени `Pace` (реальное время) | платформу, D3D |
| `minecraft/` | ассеты из jar игрока: zip, PNG, `.mcmeta`, ванильные биомы, NBT-структуры, блочные модели, рост деревьев, меши из блоков | D3D, игру, карту |
| `render/` | D3D11, вся карта: блоки, модели, границы, названия | игру, UI |
| `game/` | (`mc_sim`) `GameData` = `Content` (неизменяемые справочники, все строки) + `WorldState` (только SoA-столбцы); `World`; `Session` | вид, UI, D3D |
| `ui/` | экраны Dear ImGui; читают состояние, возвращают `UiCommands` | как меняется состояние |
| `app/` | `App` — карта; облик карты из ассетов: блоки (`terrain_look`, `biome_table`), домики, пирсы и деревья (`scenery`); `bindings.cpp` — все коды клавиш игры; `Shell` — тонкая склейка для хоста | — |
| `host/win32` | `mapcraft.exe`: окно, swap chain, ввод; всё о платформе — только здесь (долги: копия кода окна в `editor/main.cpp`, WIC в `ui/image.cpp`) | — |
| `editor/` | инструмент: `App` + свой `GameData` + панели | — |

Инварианты:
- `World` владеет `GameData` и отдаёт наружу только `const`. `WorldState` меняют только правила самого `World`.
- Библиотеки: `mc_sim` (`core/` + `game/`, без D3D, ImGui и ассетов) и `mc_game` (всё остальное, линкует `mc_sim`).
  Симуляция не включает заголовков вида — это ловит линтер.
- Время: дата — скаляр в `World`, не в `WorldState`. **Мир продвигается только `World::advance_days(n)`** —
  единственный путь: игра зовёт её из `Shell::frame` (до карты и UI, только в фазе `playing`), `mapcraft_sim` позже
  зовёт её же. Сколько дней — решает только `Pace` (`view/pace.h`) в `Shell`. Скорость 5 ограничена бюджетом кадра,
  потолка дней нет (docs/GAMEDATA.md, «Время»).
- `App` читает данные игры через `const GameData*` и не знает клавиш; камера получает `CameraInput`.
- В `Shell` объект `world_` объявлен раньше `app_`: `App` держит указатель на данные мира.
- Порядок кадра: карта → UI. Курсор — системный (игра свой не рисует).
- Перелёт камеры стартует только после `App::ensure_camera`: отложенный сброс камеры отменил бы перелёт.
- `Editor` смешивает UI и логику правки. Для инструмента это допустимо, но в игру такой шаблон не переносить.

## Намеренные особенности — не «чинить»
- **Названия на карте.** `view/labels.cpp` — перенос алгоритма названий EU4 один в один; в TU сверен с LabelPython:
  89/89, расхождение до 1e-4 px. Странности оригинала намеренные.
  - Единственное отличие: `kMinBridgedPiece` = 1 вместо 2, чтобы островки подписывались вместе с материком.
  - Группировка одна для всех режимов: регионы, культуры и религии — «страны» без столиц.
- **Названия вод** ниже по иерархии, чем названия суши: никогда не лежат на суше или на других надписях; вода, где
  название не влезает, остаётся без него.
- **Провинции после генерации заморожены.** Правки — только через `tools/mapgen/edit_provinces.py`, не
  перегенерировать. Единственный источник истины для берегов и высот — `heightmap.png` (экспорт Azgaar);
  `land.png` из него делает `tools/mapgen/heightmap.py`, руками его не правят.
- **Имена провинций** живут в двух местах: корневой `provinces.csv` (из него запекаются надписи) и колонка `name` в
  `data/setup/provinces.csv` (только для человека). Переименовывать по id в обоих.
- **Сборка карты.** `tools/labels/provinces.py` идёт до `positions.py`: города обходят буквы.
- **Порт** — пирс у каждой сухопутной провинции, граничащей с морской; его морская провинция — единственный выход
  провинции в море. Озёра не считаются. Город — один домик на участке 2×2 блока, не больше. Декоративные озёра — суша в
  игре.
- **Камера** берёт высоту рельефа через `Camera::set_ground`: `App` подаёт верх блока (вода или земля).
- **Вода непрозрачная**, под ней ничего не рисуется (решение пользователя, логика EU4); реки — блоки воды, лент рек
  нет; ступени рек — водопады (наклонная текущая вода). Каждое название — плоскость на медиане верхов блоков под
  буквами; пиксели, закрытые от камеры блоками чужих провинций (чужой группы режима), прячутся — трассировка луча,
  не буфер глубины: своя земля надпись не режет (так решил пользователь).
- **Границы** — ленты на верхах блоков (на обрыве — по верхнему краю). На ступенчатых обрывах они идут наискосок по
  стенкам; после сжатия высот это не бросается в глаза — решение пользователя: так и оставить, визуал заморожен.

## Вид (решения пользователя)
- **Рендер** следует реверсу EU4: слои встречаются в пиксельном шейдере, режим карты — это только таблица цветов.
- **Карта воксельная** (блоки), не гладкий рельеф. Деревья — настоящие майнкрафтовские (дуб, берёза, ель, джунгли…)
  как декор на карте. Исходники карты (на сетке блоков 1152×576, блок = 4×4 px карты) — README «Карта: исходники»;
  формат `world.mcmap` — docs/MAPFORMAT.md; отложенное по виду — `IDEAS.md` («Вид карты»).
- **Шрифт названий на карте** — `fonts/blockyfont.otf` (блочный, в духе Майнкрафта; в git не идёт; там же
  ChakraPetch для будущего UI), не Cinzel из TU.
- **UI — Майнкрафта, на основе Dear ImGui.** Сейчас UI — стоковый ImGui (шрифт Segoe UI, масштаб шагом 1/8);
  дальше — решение, по которому он переделывается (M6). ImGui даёт ввод, ID, обрезку, прокрутку, `ListClipper`, тултипы, поля
  ввода и таблицы; поверх — свои виджеты Майнкрафта через `imgui_internal` (`ButtonBehavior` + `ImDrawList`):
  9-slice спрайтов `gui/sprites/...` по `.mcmeta`, растровый шрифт `font/default.json` (есть кириллица), тень текста
  (сдвиг на 1 px, цвет × 0.25), точечная выборка, целочисленный GUI scale. Панели — процедурно (серый `#C6C6C6`,
  светлый край сверху-слева, тень `#555555`, чёрный контур). Иконки товаров — предметы Майнкрафта, зданий — блоки;
  флаги стран — баннеры с узорами (данные, не арт).
  - Графики — ImPlot (с M3, сначала окно цен); маленькие круговые диаграммы попов, культур и религий — своя функция
    на draw list.
  - Спрайты и шрифт берутся из установленного у игрока Майнкрафта во время работы игры; то, чего в Майнкрафте нет,
    собирается из тех же примитивов. Композицию окон пользователь проверяет по скриншотам.
- **Границы** стран — как EU4 `border5`, поверх границ провинций.
- **Цвета надписей:** чернила RGB 32,30,26, ореол 180.

## Ассеты Майнкрафта
- Проект фанатский и некоммерческий. Ассеты Mojang (текстуры, звуки, шрифт, модели) **не распространяются**: не
  класть их в репозиторий, не копировать в `assets/`, не запекать в файлы, которые можно раздать. Игра читает их из
  `.minecraft` игрока (jar версии; звуки — по индексу ассетов, когда появятся).
- **Звук** (решение пользователя, ещё не сделан): miniaudio (`ma_engine`, группы Master, Music, UI, Ambient) +
  stb_vorbis для ogg. Звуков и `sounds.json` в jar нет: они лежат в `.minecraft/assets/objects` по хэшам, путь к
  хэшу даёт `assets/indexes/<версия>.json` — для этого нужен модуль индекса ассетов в `src/minecraft/`.
- Ассеты Paradox (EU4, Victoria 2) — только для изучения, не копировать.

## Окружение
- **Сборка:** `code/build.cmd` → `code/build/release/`.
  - Нужны MSVC Build Tools (`C:\Dev\BuildTools`) и переменная `VCPKG_ROOT` (`C:\Dev\vcpkg`), триплет
    x64-windows-static. `build.cmd` находит компилятор через vswhere (последняя установка VS или Build Tools с
    MSVC x64), путь к Build Tools в нём не прописан. vcvars64 подменяет `VCPKG_ROOT` на vcpkg, встроенный в Build
    Tools; `build.cmd` возвращает значение пользователя.
  - Если открыт `mapcraft.exe` или редактор, линковка падает (LNK1168). Переименуй запущенный exe, процесс
    пользователя не убивай.
  - LNK1235 «corrupt or invalid COFF symbol table» у `mc_game.lib`: бывает, когда два exe линкуются параллельно
    (один проходит, другой падает) — просто запусти `build.cmd` ещё раз. Если падает снова — удали
    `code/build/release/mc_game.lib` и собери заново.
  - В оболочке агента задана `NoDefaultCurrentDirectoryInExePath`, из-за неё vcvars пишет «'vswhere.exe' is not
    recognized» (безвредно). Перед `build.cmd` из PowerShell: `Remove-Item Env:NoDefaultCurrentDirectoryInExePath`.
- **Шейдеры** (`render/shaders.cpp`) компилируются только при запуске. Без запуска их проверяет компилятор

## Известные долги
- `edit_provinces.py` при перенумерации не переписывает `data/setup/provinces.csv`, и данные съедут на чужие
  провинции. Исправить до первой правки карты с заполненными данными.
- `mapcraft.exe` и `mapcraft_editor.exe` дублируют Win32-код окна и ввода; редактор обрабатывает свои клавиши ImGui в
  `editor/`, мимо `app/bindings.cpp`.
- `ui/image.cpp` декодирует PNG флагов через WIC (Windows) — платформа вне `host/`; в `minecraft/` уже есть декодер PNG
  на stb.
- Загрузчик `world.mcmap` проверяет размеры не всех секций (docs/MAPFORMAT.md).
- Границы слоёв внутри `mc_game` (`view`, `minecraft`, `render`, `ui`, `app`) держатся дисциплиной: линтер проверяет
  только `mc_sim`.
- `MapData` в `mc_sim` грузит и данные вида (шрифт, глифы, геометрию границ и рек); разделить при `mapcraft_sim` (M4).
