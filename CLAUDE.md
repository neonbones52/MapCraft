# MapCraft — правила для агента

Фанатская некоммерческая глобальная стратегия в сеттинге Майнкрафта: EU4 + упрощённая экономика EU3, воксельная
карта, UI и звуки Майнкрафта. Игра `mapcraft.exe`, редактор провинций `mapcraft_editor.exe`. Начало сессии —
`NEXT.md`; из `README.md` и `docs/*.md` читай только разделы, нужные для шага. План — `docs/ROADMAP.md`. С
пользователем говори по-русски. Весь код пишет агент. Всё, что видит игрок (интерфейс, названия на карте, тексты,
`data/`), — только на английском; документация и разработка — на любом языке.

## Как работать
- **Никакого кода без понимания связей**: сначала модули, владельцы данных, время жизни, направление зависимостей.
- **Модульность**: один класс или модуль — одна ответственность; UI, правила игры и ввод не смешивать; новая
  подсистема — свой модуль в своём слое.
- **Раскладка данных** — по четырём вопросам к каждому набору данных (решение пользователя; docs/SIMULATION.md,
  «Раскладка данных»):
  1. Сколько объектов проходит цикл за раз? Тысячи — DOD; десятки — как понятнее; единицы — объект.
  2. Какие поля трогает проход? Одно-два у всех объектов — SoA; все поля одного объекта — структура (AoS).
  3. Тело цикла одинаковое для всех — можно векторизовать; ветвистая логика по шагам (бой, ИИ, поиск пути) —
     скалярный код, SoA ему только мешает.
  4. Как часто? Каждый день по всему миру — да; раз при загрузке или при правке в редакторе — нет.

  Типы `mc_sim` — при любой раскладке: индексы `u16` (провинции, страны), `u8` (короткие списки); балансы и
  требования — `i64`, 10⁶ крупинок на изумруд (`core/money.h`); модификаторы и бой — `Fixed` (`core/fixed.h`);
  остальное — `float` по правилам детерминизма; флаги и множества — маски `u64`. В дневном тике нет выделений
  памяти. Набор инструкций — SSE2.
- **Симуляция строго детерминирована** (lockstep): одинаковые команды → бит в бит одинаковое состояние на всех
  машинах при любом числе потоков. Для `mc_sim` (`core/`, `game/`), не для `view/`; подробно — docs/SIMULATION.md,
  «Детерминизм»:
  1. `/fp:precise`, без `/fp:fast` и FMA; один набор инструкций.
  2. Без CRT `exp`, `pow`, `log`, `sin` — только `det_<имя>` из `core/det_math.h`.
  3. Случайность — только `random(seed, день, сущность, назначение)`; у UI свой генератор.
  4. Только дни: `dt`, кадры и часы в симуляцию не попадают.
  5. Без `unordered_map` и сортировок по адресам; сортировка — с полным порядком (при равенстве — id).
  6. Параллельность — фиксированное разбиение, суммы в фиксированном порядке, без атомарных накоплений `float`.
  7. Разбор данных без локали: `std::from_chars`, не `atof`/`stod`.
  8. Состояние UI (выделение, камера, окна) отдельно от состояния мира.
  9. Сохранение бит в бит; кэши после загрузки пересчитываются детерминированно.
  10. Бот только на хосте и выдаёт обычные команды; параллельные решения сортируются по (страна, команда).
  11. Контрольная сумма — только в `mapcraft_sim`; debug-сборки нет и не будет.
  12. Нет `std::*_distribution`; MXCSR выставляется явно в потоке симуляции.

  Линтер `tools/lint/sim_lint.py` — первый шаг каждой сборки: запрещённое в `core/` и `game/` роняет сборку.
- **Размер файлов**: делить, когда у файла больше одной ответственности; ~1000 строк — повод проверить, не причина.
- **Делай только запрошенный шаг.** Спецификации фич даёт пользователь; сам фичи не планируй и не начинай.
- **Ход работ**: срезы — `docs/ROADMAP.md`, механики — `docs/EU3.md`. `NEXT.md` — три ближайших шага, только из
  роадмапа (иное — только от пользователя); новые идеи — строкой в `IDEAS.md`; шагов нет — сказать «роадмап
  исчерпан». В начале сессии прочитать `NEXT.md`, в конце — обновить. Результат проверяет пользователь.
- **Отладочное в exe — в рамке** (docs/CODE.md, «Отладочное»): только поля `DevOptions` (`app/dev_options.h`), окно
  «Dev» по F9; флагов командной строки под отладку нет (кроме `mapcraft_editor --check`). Отладочное только
  показывает, в `mc_sim` его нет, действия отладки — обычные команды. Не больше ~15 переключателей, каждый — строкой
  в docs/CODE.md; просроченные удалить в конце среза. Экономику и ботов — сначала в `mapcraft_sim`.
- **Тесты — только там, где глазами не проверить**: деньги (через `ledger`), детерминизм, сценарии `mapcraft_sim`,
  линтер `mc_sim`. Рендер и UI — без тестов. Тест проверяет свойство игры, а не реализацию; не подгоняется под код:
  упал — чинится код или прямо говоришь пользователю; ослабить — только с его согласия. Разовых проверочных
  программ не писать. Проверка — `code/build.cmd` без предупреждений; в отчёте — что собрано, что не запускал, что
  не проверено.
- **Память проекта — только в папке проекта** (`CLAUDE.md`, `README.md`, `docs/`, `NEXT.md`, `IDEAS.md`); вне
  проекта (`~/.claude/.../memory` и т. п.) ничего не писать. Новое правило, решение или особенность — в документацию.
- **Без костылей**: чини причину; правь исходник (PNG и CSV карты, `data/`), а не сгенерированное.
- **Документация описывает текущее состояние** и инварианты, не летопись; меняешь систему — правь её документ в том
  же шаге. Исключение — планы (`docs/ROADMAP.md`, `NEXT.md`, `IDEAS.md`, `docs/EU3.md`, `docs/ECONOMY.md`,
  `docs/SIMULATION.md`, `docs/UI.md`): сделанное оттуда убирается или переносится в документ системы.
- **Документация не пересказывает содержимое `data/`**: ни количеств, ни столиц, ни списков стран. Сводку печатают
  `mapcraft_editor --check` или `mapcraft_sim`.
- **Git**: `origin` = github.com/neonbones52/MapCraft, `main`; коммит и пуш — только по просьбе; бинарники (png, ttf,
  npz, ogg, jar…) в репозиторий не идут.
- **Игровые данные** — CSV в `data/`; заполняет их пользователь в `mapcraft_editor`.
- Не проси computer-use доступ к окну редактора или игры. Не сканируй диски целиком — пути известны.

## Архитектура (`code/src`; по папкам — docs/CODE.md)
| Слой | Что | Не знает |
|---|---|---|
| `core/` | (`mc_sim`) карта для симуляции (`MapData`, `world.mcmap`), CSV, лог, `det_math.h` | вид, платформу, игру |
| `view/` | ввод, камера, раскладка названий EU4, темп `Pace`; карта для вида `MapView` | платформу, D3D |
| `minecraft/` | ассеты из jar игрока: zip, PNG, `.mcmeta`, биомы, структуры, модели, деревья, меши | D3D, игру, карту |
| `render/` | D3D11, вся карта: блоки, модели, границы, названия | игру, UI |
| `game/` | (`mc_sim`) `GameData` = `Content` + `WorldState` + `Cache`; `World`; `Session`; модификаторы; бой `combat.h`; экономика `game/economy/` | вид, UI, D3D |
| `ui/` | экраны Dear ImGui; читают состояние, возвращают `UiCommands` | как меняется состояние |
| `app/` | `App` — карта и её облик из ассетов; `bindings.cpp` — все клавиши игры; `Shell` — склейка для хоста | — |
| `host/win32` | всё о платформе — только здесь (окно, ввод, D3D-цель, лог); `main.cpp` — `mapcraft.exe` | — |
| `headless/` | `mapcraft_sim.exe`: `mc_sim` без окна — сценарий, прогон, контрольная сумма | вид, платформу, D3D |
| `editor/` | `mapcraft_editor`: `App` + свой `GameData` + панели; окно из `host/win32` | — |

Граф слоёв — таблица в `tools/lint/layers.py`, линтер охраняет её первым шагом сборки. Новая папка или ребро —
решение с пользователем.

Инварианты:
- `World` владеет `GameData` и отдаёт наружу только `const`; `WorldState` меняют только правила `World`.
- Библиотеки: `mc_sim` (`core/` + `game/`, без D3D, ImGui и ассетов), `mc_game` (остальное); `mapcraft_sim` — только
  `mc_sim`.
- Данные игры: **сохраняется** (`WorldState`, `game/saved_state.h`), **контент** (`Content`), **кэш** (пересчитывается
  после загрузки). Новый столбец `WorldState` — строкой в X-macro своей таблицы (`game/game_data.h`); поле вне
  списков — явно в `for_each_saved`.
- **Деньги меняет только `ledger`** (`game/economy/ledger.h`: `mint`, `transfer`, `settle`); деньги не замкнуты:
  доход из ничего, расходы в никуда.
- Дата — скаляр в `World`. **Мир продвигается только `World::advance_days(n)`** (игра — из `Shell::frame` в фазе
  `playing`, `mapcraft_sim` — её же); сколько дней — решает только `Pace` (`view/pace.h`). **Приказы игрока, бота и
  отладки — только команды** одной очереди: `World::post`, исполняет `World::run_commands` между днями.
- `App` читает данные игры через `const GameData*` и не знает клавиш; камера получает `CameraInput`.
- `Editor` смешивает UI и логику правки — для инструмента допустимо, в игру не переносить.

## Намеренные особенности — не «чинить»
- **Названия на карте** — перенос алгоритма EU4 один в один, кроме `kMinBridgedPiece` = 1 (docs/RENDER.md).
- **Названия вод** ниже по иерархии, чем суши; не влезает — вода без названия (docs/MAPFORMAT.md).
- **Провинции заморожены**: правки только `tools/mapgen/edit_provinces.py`; берега и высоты — только из
  `heightmap.png`, `land.png` руками не правят; `labels/provinces.py` идёт до `positions.py` (docs/MAPBUILD.md). Имена
  провинций — в двух местах, переименовывать по id в обоих (docs/GAMEDATA.md, `setup/provinces.csv`).
- **Порт, город, озёра**: пирс — единственный выход провинции в море, город — один домик 2×2, декоративные озёра —
  суша в игре (docs/MAPBUILD.md, «Город и порт»).
- **Камера** берёт высоту рельефа через `Camera::set_ground`.
- **Вода непрозрачная**, реки — блоки воды; названия — плоскость на медиане, прячутся трассировкой луча, своя земля
  их не режет (docs/RENDER.md).
- **Границы** на ступенчатых обрывах идут наискосок по стенкам.

## Вид (решения пользователя)
- Рендер следует реверсу EU4: слои встречаются в пиксельном шейдере, режим карты — только таблица цветов
  (docs/RENDER.md). Карта воксельная, деревья — майнкрафтовские; визуал заморожен.
- UI — Майнкрафта на основе Dear ImGui: свои виджеты из спрайтов и шрифта jar игрока (docs/UI.md).

## Ассеты
Ассеты Mojang (текстуры, звуки, шрифт, модели) **не распространяются**: не класть в репозиторий, не копировать в
`assets/`, не запекать в раздаваемые файлы — игра читает их из `.minecraft` игрока. Ассеты Paradox (EU3, EU4,
Victoria 2) — только для изучения, не копировать.

## Окружение
- **Сборка:** `code/build.cmd` → `code/build/release/`. Нужны MSVC Build Tools (`C:\Dev\BuildTools`, находятся через
  vswhere) и `VCPKG_ROOT` (`C:\Dev\vcpkg`), триплет x64-windows-static; `build.cmd` сам возвращает `VCPKG_ROOT`,
  который подменяет vcvars64.
  - Перед `build.cmd` из PowerShell: `Remove-Item Env:NoDefaultCurrentDirectoryInExePath`.
  - LNK1168 — открыт `mapcraft.exe` или редактор: переименуй запущенный exe, процесс пользователя не убивай.
  - LNK1235 у `mc_game.lib`: lib не удалять — сохранить копию, проверить её (`lib /list`, `dumpbin
    /linkermember`), повторить сборку как есть, записать результат (docs/CODE.md, «Известные долги»).
- Шейдеры компилируются при запуске; проверка без запуска — `fxc.exe` (docs/RENDER.md). Python — docs/MAPBUILD.md.
- Правка срезами между якорями: якорь уникален, срез не пустой. Bash-heredoc с Python портит обратные косые в
  строках — такие правки инструментом Edit, потом проверить файл.
- Справочные проекты — только изучать, код не копировать:
  - **EU4** (`C:\Games\EUIV`) и реверс eu4.exe с pdb `C:\Dev\Projects\eu4\archeologyEU4\` (`Render`, `Labels`, `UtilityAI`).
  - **Project Alice** (`C:\Dev\Projects\ProjectAlice`) — образец только детерминизма, lockstep и headless, не
    экономики; код GPL-3, идеи и числа — можно.
  - **Вики EU3** (eu3.paradoxwikis.com) — правила экономики и войны; читать во встроенном браузере по одной статье
    (WebFetch получает страницу-проверку, на частые запросы — 429). Формулы и числа — можно, тексты — нет.
  - **BattleSim** (`C:\Dev\Projects\eu4\BattleSim`, проект пользователя) — бой EU4, образец боя M6.
  - **CinemaShort** (`C:\Dev\Projects\CinemaShort`, проект пользователя) — модели сущностей, ходьба и удар из jar.
  - **Tamriel Universalis** (только github.com/neonbones52/TamrielUniversalis) — прежний проект; код оттуда не
    переносить без решения пользователя.
