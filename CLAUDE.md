# MapCraft — правила для агента

Фанатская некоммерческая глобальная стратегия в сеттинге Майнкрафта: EU4 + упрощённая экономика EU3 (решение
пользователя), воксельная карта, UI и звуки Майнкрафта. Отдельная игра `mapcraft.exe` и редактор провинций
`mapcraft_editor.exe`. Начало сессии — `NEXT.md`; из `README.md` и `docs/*.md` читай только разделы, нужные для шага. План — `docs/ROADMAP.md`. С пользователем говори по-русски.
Весь код пишет агент. Всё, что видит игрок (интерфейс, названия на карте, тексты, `data/`), — только на английском;
документация и разработка — на любом удобном языке.

## Как работать
- **Никакого кода без понимания связей.** Перед новым слоем или фичей определи модули, владельцев данных, время жизни
  объектов и направление зависимостей. Код — только после этого.
- **Модульность.** Один класс или модуль — одна ответственность. Никогда не сваливать в один класс UI, правила игры и
  ввод. Новая подсистема — свой модуль в своём слое (см. «Архитектура»).
- **DOD, SoA, SIMD-friendly — для ВСЕХ данных `mc_sim`** (решение пользователя): и состояния мира, и рабочих данных
  тика (индексы, промежуточные суммы, списки армий и купцов); временные данные исключением не бывают (почему —
  docs/SIMULATION.md, «Раскладка данных»). Где раскладка даёт выигрыш, она обязательна:
  - индексы: `u16` для провинций и стран, `u8` для списков (товары, здания, типы полков);
  - числа — `float` с правилами детерминизма; **балансы и требования** (всё, что лежит на счету и переходит из рук
    в руки) — `i64`, 10⁶ крупинок на изумруд (`core/money.h`, решение пользователя; docs/ECONOMY.md, «Деньги в i64»);
  - столбцы выровнены на 64 байта, длина дополнена до кратной 16; в горячих данных нет строк и указателей;
  - циклы идут по столбцам, плотными проходами без ветвлений внутри, где это возможно (чтобы компилятор векторизовал);
  - рабочие данные тика: индексы, которые меняются только с данными, строятся при загрузке; рабочие столбцы
    переживают день и переиспользуются; в тике нет выделений памяти и массивов структур (раскладка экономики — docs/ECONOMY.md, «Код»);
  - флаги и множества — битовые маски на `u64` (коры, здания, условия, война, осада), не столбцы `bool` и не списки;
  - целевой набор — SSE2 (без `/arch`): 4 `float`, 4 `u32` или 2 `i64` за инструкцию.
  Это касается и экономики EU3-lite, и войны; раскладку выбирает и отвечает за неё агент, в ревью среза её
  проверяют так же, как детерминизм.
- **Симуляция строго детерминирована** (мультиплеер будет, lockstep): одинаковые команды → бит в бит одинаковое
  состояние на всех машинах, при любом числе потоков. Правила — для `mc_sim` (`core/`, `game/`); на `view/` не
  распространяются. Подробности — docs/SIMULATION.md, «Детерминизм»:
  1. `/fp:precise`, без `/fp:fast` и сжатия в FMA; один набор инструкций, без выбора во время работы.
  2. Без CRT `exp`, `pow`, `log`, `sin`: только свои `det_<имя>` в `core/det_math.h`.
  3. Случайность — только счётный генератор `random(seed, день, сущность, назначение)`; у UI — свой генератор.
  4. Только дни: `dt`, частота кадров и часы в симуляцию не попадают.
  5. `unordered_map` в `mc_sim` запрещён; без сортировок по адресам; сортировка — с полным порядком (при равенстве — id).
  6. Параллельность — фиксированное разбиение и суммы в фиксированном порядке, без атомарных накоплений `float`.
  7. Разбор данных не зависит от локали: `std::from_chars`, не `atof` или `stod`.
  8. Состояние UI (выделение, камера, окна) отдельно от состояния мира.
  9. Сохранение бит в бит; кэши после загрузки пересчитываются детерминированно.
  10. Бот только на хосте, выдаёт обычные команды; параллельные решения сортируются по (страна, команда).
  11. Контрольная сумма — только в `mapcraft_sim`; debug-сборки нет и не будет; в сети она станет частью протокола.
  12. Нет `std::*_distribution`; MXCSR выставляется явно в потоке симуляции.
  Линтер `tools/lint/sim_lint.py` — первый шаг каждой сборки: ловит запрещённое в `core/` и `game/` и роняет сборку.
- **Размер файлов.** Файл делится, когда у него больше одной зоны ответственности, то есть его нельзя описать одним
  предложением. Больше ~1000 строк — повод проверить, но не причина делить.
- **Делай только запрошенный шаг.** Спецификации новых фич даёт пользователь. Сам фичи не планируй и не начинай.
- **Ход работ.** План — срезы `docs/ROADMAP.md`, механики для них — каталог `docs/EU3.md`. `NEXT.md` — три ближайших шага, ведёт агент только из роадмапа: чего
  там нет — только от пользователя, новые идеи — строкой в `IDEAS.md`; шагов нет — прямо сказать «роадмап исчерпан».
  Начало сессии — прочитать `NEXT.md`, конец — обновить его. Результат проверяет пользователь сам.
- **Отладочное в exe — в рамке** (решение пользователя; README, «Отладочное»): переключатели — только поля
  `DevOptions` (`app/dev_options.h`), меняются в окне «Dev» по F9, окно строится по структуре; флагов командной
  строки и разбора аргументов под отладку нет (кроме `mapcraft_editor --check`), сохранение — одним файлом целиком.
  Отладочное только показывает (оверлеи, окна, графики, режимы рендера): правила от него не ветвятся, в `mc_sim` его
  нет, действия отладки — обычные команды. Не больше ~15 переключателей, каждый — строкой в README (имя, зачем, до
  когда), просроченные — удалить в конце среза. Экономику и ботов — сначала в `mapcraft_sim`, в игре — живое на карте.
- **Тесты — только там, где глазами не проверить:** деньги (только через `ledger`), детерминизм, сценарии
  `mapcraft_sim.exe` (docs/SIMULATION.md), линтер запрещённого в `mc_sim`. Рендер, UI, домики, деревья — без тестов,
  их проверяет пользователь глазами. Тест проверяет свойство, важное для игры («после мира провинция у победителя»,
  «два прогона бит в бит»), а не детали реализации; никогда не подгоняется под код, чтобы стать зелёным: упал —
  чинится код, или прямо пиши пользователю, что не так; ослабить проверку — только с его согласия. Зелёный тест не
  значит «работает»: в отчёте пиши, что не проверено.
  Разовых проверочных программ (`check.cpp` и подобного) не писать нигде. Проверка — `code/build.cmd` без
  предупреждений; игру и вид проверяет пользователь в `mapcraft.exe`; в отчёте — что собрано, что не запускал и не видел.
- **Вся память проекта — только в папке проекта** (`CLAUDE.md`, `README.md`, `docs/`, `NEXT.md`, `IDEAS.md`); вне
  проекта (`~/.claude/.../memory` и т. п.) ничего не писать. Новое правило, решение или особенность — в документацию.
- **Без костылей.** Чини причину, а не обходи её. Правь исходник (PNG и CSV карты, `data/`), а не сгенерированное.
- **Документация описывает текущее состояние**, инварианты и особенности, а не летопись; меняешь систему — правь её
  документ в том же шаге. Исключение — невоплощённые планы и решения (`docs/ROADMAP.md`, `NEXT.md`, `IDEAS.md`,
  `docs/EU3.md`, `docs/ECONOMY.md`, `docs/SIMULATION.md`, `docs/UI.md`): сделанное оттуда убирается или переносится в документ системы.
- **Git:** `origin` = github.com/neonbones52/MapCraft, `main`; коммит и пуш — только по просьбе; бинарники (png, ttf,
  npz, ogg, jar…) в репозиторий не идут.
- **Игровые данные** — CSV в `data/`; заполняет их пользователь в `mapcraft_editor`.
- Не проси computer-use доступ к окну редактора или игры. Не сканируй диски целиком — пути известны.

## Архитектура (`code/src`; подробно по папкам — README, «Код»)
| Слой | Что | Не знает |
|---|---|---|
| `core/` | (`mc_sim`) карта для симуляции (`MapData`, `world.mcmap`), CSV, лог, `det_math.h` | вид, платформу, игру |
| `view/` | ввод, камера, раскладка названий EU4, темп `Pace`; карта для вида `MapView` | платформу, D3D |
| `minecraft/` | ассеты из jar игрока: zip, PNG, `.mcmeta`, биомы, структуры, модели, деревья, меши | D3D, игру, карту |
| `render/` | D3D11, вся карта: блоки, модели, границы, названия | игру, UI |
| `game/` | (`mc_sim`) `GameData` = `Content` + `WorldState` + `Cache`; `World`; `Session`; модификаторы; экономика `game/economy/` | вид, UI, D3D |
| `ui/` | экраны Dear ImGui; читают состояние, возвращают `UiCommands` | как меняется состояние |
| `app/` | `App` — карта и её облик из ассетов; `bindings.cpp` — все клавиши игры; `Shell` — склейка для хоста | — |
| `host/win32` | всё о платформе — только здесь (окно, ввод, D3D-цель, лог); `main.cpp` — `mapcraft.exe` | — |
| `headless/` | `mapcraft_sim.exe`: `mc_sim` без окна — сценарий, прогон, контрольная сумма (docs/SIMULATION.md) | вид, платформу, D3D |
| `editor/` | `mapcraft_editor`: `App` + свой `GameData` + панели; окно из `host/win32` | — |

**Граф слоёв** (кто кого включает, где какие библиотеки; симуляция не включает вид) — таблица в `tools/lint/layers.py`,
линтер охраняет её первым шагом каждой сборки. Новая папка или ребро — решение с пользователем, правится там.

Инварианты:
- `World` владеет `GameData` и отдаёт наружу только `const`. `WorldState` меняют только правила самого `World`.
- Библиотеки: `mc_sim` (`core/` + `game/`, без D3D, ImGui и ассетов), `mc_game` (остальное); `mapcraft_sim` — только `mc_sim`.
- Данные игры размечены: **сохраняется** (`WorldState`, по столбцам — `game/saved_state.h`), **контент** (`Content`),
  **кэш** (рабочие данные правил, пересчитываются после загрузки). Новый столбец `WorldState` — одной строкой в
  списке столбцов своей таблицы (X-macro, `game/game_data.h`): из него поле, `resize`, `for_each_saved` и, для
  `setup`, чтение и запись `data/setup`. Поле вне списков — явно в `for_each_saved` (иначе его не увидят дамп и
  контрольная сумма; `static_assert` на размер напомнит).
- **Деньги меняет только `ledger`** (`game/economy/ledger.h`): `mint` (доход из ничего), `transfer` и пакетный
  `settle`. Деньги не замкнуты (решение пользователя, EU3-lite): доход появляется из ничего, расходы уходят в никуда.
- Дата — скаляр в `World`, не в `WorldState`. **Мир продвигается только `World::advance_days(n)`**: игра зовёт её из
  `Shell::frame` (до карты и UI, только в фазе `playing`), `mapcraft_sim` — её же. Сколько дней — решает только
  `Pace` (`view/pace.h`) в `Shell` (docs/GAMEDATA.md, «Время»). **Приказы игрока, бота и отладки — только команды**
  одной очереди: `World::post`, исполняет `World::run_commands` между днями (docs/GAMEDATA.md, «Команды»).
- `App` читает данные игры через `const GameData*` и не знает клавиш; камера получает `CameraInput`.
- `Editor` смешивает UI и логику правки. Для инструмента это допустимо, но в игру такой шаблон не переносить.

## Намеренные особенности — не «чинить»
- **Названия на карте** — перенос алгоритма EU4 один в один, странности оригинала намеренные; единственное отличие —
  `kMinBridgedPiece` = 1 (docs/RENDER.md, «Названия на карте»).
- **Названия вод** ниже по иерархии, чем суши; не влезает — вода без названия (docs/MAPFORMAT.md, «Названия провинций»).
- **Провинции заморожены**: правки только `tools/mapgen/edit_provinces.py`; берега и высоты — только из
  `heightmap.png`, `land.png` руками не правят; `labels/provinces.py` идёт до `positions.py`, чтобы города обходили
  буквы (README, «Карта: исходники» и «Карта: сборка»). Имена провинций — в двух местах, переименовывать по id в
  обоих (docs/GAMEDATA.md, `setup/provinces.csv`).
- **Порт, город, озёра**: пирс — единственный выход провинции в море, город — один домик 2×2, декоративные озёра —
  суша в игре (README, «Город и порт»).
- **Камера** берёт высоту рельефа через `Camera::set_ground` (docs/RENDER.md, «Камера»).
- **Вода непрозрачная**, реки — блоки воды; названия — плоскость на медиане, прячутся трассировкой луча, своя земля
  их не режет (docs/RENDER.md, «Поверхность» и «Названия на карте»).
- **Границы** на ступенчатых обрывах идут наискосок по стенкам — так и оставить (docs/RENDER.md, «Границы»).

## Вид (решения пользователя)
- Рендер следует реверсу EU4: слои встречаются в пиксельном шейдере, режим карты — только таблица цветов
  (docs/RENDER.md). Карта воксельная, деревья — настоящие майнкрафтовские; визуал заморожен.
- UI — Майнкрафта, на основе Dear ImGui: свои виджеты поверх ImGui из спрайтов и шрифта jar игрока (docs/UI.md).

## Ассеты
- Проект фанатский и некоммерческий. Ассеты Mojang (текстуры, звуки, шрифт, модели) **не распространяются**: не
  класть их в репозиторий, не копировать в `assets/`, не запекать в файлы, которые можно раздать. Игра читает их из
  `.minecraft` игрока (jar версии; звуки — по индексу ассетов, IDEAS.md, «Звук»). Ассеты Paradox (EU3, EU4,
  Victoria 2) — только для изучения, не копировать.

## Окружение
- **Сборка:** `code/build.cmd` → `code/build/release/`. Нужны MSVC Build Tools (`C:\Dev\BuildTools`; `build.cmd`
  находит компилятор через vswhere — последняя VS или Build Tools с MSVC x64, путь не прописан) и `VCPKG_ROOT`
  (`C:\Dev\vcpkg`), триплет x64-windows-static. vcvars64 подменяет `VCPKG_ROOT` на встроенный vcpkg, `build.cmd`
  возвращает значение пользователя.
  - LNK1168 — открыт `mapcraft.exe` или редактор: переименуй запущенный exe, процесс пользователя не убивай.
  - LNK1235 «corrupt or invalid COFF symbol table» у `mc_game.lib` — причина не найдена («Известные долги»). Lib
    не удалять: сначала сохранить копию и проверить её (`lib /list`, `dumpbin /linkermember`), потом повторить
    сборку как есть, и записать результат в «Известные долги».
  - В оболочке агента задана `NoDefaultCurrentDirectoryInExePath` (vcvars пишет безвредное «'vswhere.exe' is not
    recognized»): перед `build.cmd` из PowerShell — `Remove-Item Env:NoDefaultCurrentDirectoryInExePath`.
- Шейдеры компилируются только при запуске; проверка без запуска — `fxc.exe` (docs/RENDER.md). Python — README,
  «Карта: сборка».
- Правка файлов: правя срезами между якорями, проверяй, что якорь уникален, а срез не пустой. Bash-heredoc с
  Python-скриптом портит обратные косые в строках (`'\n'`, `\v`): такие правки — инструментом Edit, потом проверь файл.
- Справочные проекты — только изучать, код не копировать:
  - **EU4** (`C:\Games\EUIV`) и реверс eu4.exe с pdb `C:\Dev\Projects\eu4\archeologyEU4\` (`Render`, `Labels`, `UtilityAI`).
  - **Project Alice** (`C:\Dev\Projects\ProjectAlice`) — открытый движок Victoria 2, образец только детерминизма,
    lockstep и headless, не экономики (решение пользователя). Код GPL-3; идеи и числа-ориентиры — можно
    (docs/ECONOMY.md, «Что нельзя»).
  - **Вики EU3** (eu3.paradoxwikis.com) — правила экономики и войны. WebFetch получает страницу-проверку: читать во
    встроенном браузере, по одной статье (на частые запросы и поиск — 429). Формулы и числа — можно, тексты — нет.
  - **BattleSim** (`C:\Dev\Projects\eu4\BattleSim`, проект пользователя) — бой EU4; образец боя M6 (docs/ROADMAP.md).
  - **CinemaShort** (`C:\Dev\Projects\CinemaShort`, проект пользователя) — модели сущностей и ходьба из jar; образец
    фигурок армий M5 (docs/ROADMAP.md).
  - **Tamriel Universalis** (только github.com/neonbones52/TamrielUniversalis) — прежний проект: гладкий рельеф,
    Blender-модели, хост SKSE. Код оттуда не переносить без решения пользователя.

## Известные долги
- LNK1235 на `mc_game.lib` (дважды 26.11.2026, обе — при пересборке `mc_sim` и `mc_game` разом): причина не найдена.
  Параллельная линковка двух exe — не причина: в графе Ninja оба exe ждут готовый lib и только читают его; семь
  пересборок в тех же условиях ошибку не дали — она случайная. Версии: lib на диске битый (тогда — `mc_game`/`mc_sim`
  как OBJECT-библиотеки CMake, без архива) или свежий файл трогал внешний процесс; 26.11.2026 пользователь добавил
  `C:\Dev` в исключения Defender — повторится, значит не Defender. При повторе — «Окружение», LNK1235.
